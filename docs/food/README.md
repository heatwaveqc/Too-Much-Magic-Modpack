## Orthogonal dimensions
* Identity: concrete registry ID, source, installed presence, variant/components, review status, native tags.
* Biological/ingredient origin: fruit, berry, vegetable, fungi, grain, legumes, nuts, terrestrial meat, fish, other seafood, aquatic plants, dairy, egg, blood, mineral; allow mixed origins. Preparation: raw, cut, cooked, charred, preserved, fermented, mixed, grain-free, intermediate. Explicit equivalence groups only where the same ingredient is interchangeable, not every member of a biological class.
* Native use: food properties, nutrition/saturation/effects, custom-use, placeable feast, drink, utensil/ingredient only, edible only by transformed species, no food. Preserve cost, cooldown, remainders, components, resource gates. Track tags vs native use separately. A tag does not guarantee edible or safe. Alcohol, poisonous/spoiled, magical/reusable, ordinary blood and ritual/special blood are independent flags. Unknown is not deny and not allow.
* Consumer decisions: cooking recognition and substitution; JAWR vampire nourishment and werewolf eligibility by native form; Cave/Forest/Sea separately; Progression states/food rites/consumption effects; lich/archlich/dracolich native authority; economy valuation. Keep provenance and explicit exception reasons for each. Do not derive any vampire blood, dragon allowance, XP, rite, or EMC from a generic food tag. No code added to Progression; that engine remains the sole owner of executable state policies.
