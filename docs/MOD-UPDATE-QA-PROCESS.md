# Mod-update QA process — immutable isolated trials

**Updated 2026-11-21 after the four-mod server-smoke investigation.** Applies to Too Much Magic (TMM), Minecraft 1.21.1 / NeoForge, Packwiz, first-party Gradle modules and Prism Launcher.

**Policy:** An update is not ready for integration merely because its provider announces a release, quick CI passes, or a server reaches `Done`. The eight canonical levels remain separate: Repository CI, Module CI, Integration Preflight, Integration Assembly, Server Boot Smoke, Prism QA Package, Client Launch Smoke and Gameplay Acceptance. Game-changing or beta updates still need owner review. Server smoke and Prism packaging run **only on fresh owner authorization**, never on PR/push/schedule or an automatic retry.

## Reusable procedure

1. **Survey the full active roster before choosing updates.** Derive the *installed* baseline from `manifest/mods.json`, `index.toml`, every active `mods/*.pw.toml`, the exact Minecraft/NeoForge target and first-party compile dependencies. Independently check upstream release pages and provider IDs for each active mod; note versions with no appropriate build, deprecated dependencies, side restrictions, holds and beta-only candidates. Reconcile the mandatory live-test inclusion register and all ready feature branches for a *comprehensive* QA build. A four-mod experiment is **not** a substitute for this full-roster survey.
2. **Freeze candidate identity and scope.** Record each baseline version, selected exact newer filename, provider project/file/version ID, stable or beta channel, upstream notes, dependencies, expected behavior changes and explicit approval/hold decisions. Keep an isolated experiment PR and a full 40-hex immutable candidate commit. Do not change the moving shared `test/full-integration` branch to force a trial.
3. **Resolve real binaries and pin content hashes.** Use official Modrinth metadata when it lists the exact release; if absent, use a *specifically verified official* CurseForge file ID/URL, not an arbitrary mirror or latest link. Download and validate JAR signatures/magic, size bounds and SHA-512; include enough size headroom for large Goety packages (~94 MiB). Track exact origin and bytes. Never commit upstream JARs or blindly substitute a nearby version. Ars Elemental 0.7.11.3 is a **beta** and must stay experimental absent a separate owner beta-promotion decision.
4. **Prepare coherent Packwiz changes.** Modify only approved mod pins and matching `manifest/mods.json` version/channel entries. Recalculate each affected `index.toml` SHA-256 entry and the `pack.toml` index hash. Validate the complete enabled roster, server/client sides, filenames and hashes. Keep a full rollback source SHA and binary/metadata provenance.
5. **Use the canonical clean integration assembler, not the experimental branch.** The assembler intentionally accepts **only** a clean `test/full-integration` checkout at current remote HEAD. Preserve this protection. In an *ephemeral separate checkout*, run standard assembly/read-only preflight, then overlay only the independently verified updated pins and matching manifest entries; fail if any baseline pin or entry differs from the frozen original source. Revalidate Packwiz and the full QA inventory after overlay. Do not restore old donor directories over newer merged content.
6. **Audit first-party compile ABI before attempting game boot.** Besides Packwiz, inspect exact-name compile allowlists such as `compat/economy/build.gradle` `exactJars`. New EvilCraft, Neo Vitae and Goety names can differ from those hardcoded source pins even when their JARs have been downloaded and hash verified. In the isolated update checkout only, change reviewed **old/new exact filename pairs**, preserve the allowlist and strict existence checks, and fetch the classpath against the new SHA-512-pinned metadata. Compile and unit-test all selected first-party modules. Do not introduce generic version wildcards, false aliases or unchecked files to silence a failure.
7. **Ask for one owner-authorized server smoke per attempt.** From issue [#291](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/issues/291), use the fresh exact command `/tmm-update smoke experiment/<branch> <40hex-candidate-sha> <unique-32-lowercase-hex-nonce>` (or `prism` for a server-gated Prism build). The guard verifies owner GitHub ID, comment freshness/non-editing, open experimental PR and exact head, green quick CI, in-flight manual full-build exclusion and one-shot receipt tag. Never replay an authorization, retry automatically after failure or interpret a dispatch receipt as a passed build.
8. **Prove actual server behavior, not just compilation.** After assembly, verify all four selected update files survive, all installed JARs hash-check, four first-party JARs compile/install/load, and NeoForge reaches `Done` and exits cleanly. Include a dropped Stone item that ticks several times to catch KubeJS global-entity regressions, and reject server KubeJS errors. Keep the server log, pinned metadata, hashes, source/rollback SHAs and precise PASS/FAIL stage. Do not infer client or gameplay acceptance from a successful server.
9. **Create a Prism artifact only after a new successful server boot.** A Prism install URL must refer to a **GitHub-reachable immutable commit containing the actual updated Packwiz hashes**; the original experiment commit does *not* contain those ephemeral updates. Commit only the already server-tested assembly/overlay text to a disposable local QA snapshot, push an isolated `qa-update-prism/<run>-<attempt>` annotated **tag only** (never push a shared branch), verify remote `pack.toml` bytes, and build with `scripts/build_full_integration_prism.py` plus official packwiz bootstrap. Use the known **single-level direct-import ZIP** artifact layout (no nested ZIP), include the exact selected four first-party JARs, QA-only preferences and machine-readable expected client JAR hashes. Do not bundle upstream mod JARs, actual owner settings or saves. Upload as `Too-Much-Magic-Four-Mod-Update-Prism-EXPERIMENTAL`; **do not replace the rolling unstable release**, claim stable status or approve a beta.
10. **Complete client and gameplay acceptance.** On a clean disposable Prism instance/world, run the focused test cases below, inspect `latest.log`/crash logs and record the exact source snapshot SHA plus each pass/fail. Distinguish baseline defects from update regressions by reproducing with the frozen known-good comparison build where possible. Promotion to `test/full-integration` is a separate integration decision; promoting an experimental beta requires an explicit exception.

## 2026-11-21/22 case study — why the checkpoints exist

| Attempt | Real result | Process lesson |
| --- | --- | --- |
| First update smoke [#44982155537](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/actions/runs/44982155537) | **REFUSED before JAR download**: authorization guard mistook hundreds of unrelated automatic quick jobs for conflicting full QA | Concurrency inventory must filter only actual manual full-build workflows; fail closed for incomplete API pages, and keep unit tests for unrelated PR/push activity |
| Second [#44982791320](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/actions/runs/44982791320) | Download and hashes passed; assembler refused to run outside clean `test/full-integration` | Assemble a pristine separate baseline, then overlay the exact candidate; never weaken assembler branch/cleanliness guards |
| Third [#44983928698](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/actions/runs/44983928698) | All pins and assembly passed; Economy Gradle demanded old `evilcraft-1.2.100` filename although `1.2.102` was verified | Review *independent compile allowlists* and ABI requirements for updated mods before first-party build; fix only exact reviewed names |
| Fourth [#44984328474](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/actions/runs/44984328474) | **QA-SERVER PASS:** 222 active pack mods, 205 installed server-side/dual-side JARs, 4 first-party JARs; modded `Done`, dropped Stone tick, no flagged KubeJS errors, clean stop exit 0 | A true server smoke is valuable compatibility evidence but leaves **QA-PRISM, QA-CLIENT and QA-GAMEPLAY unproven** |

Repairs were reviewed and merged as [PR #466](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/pull/466), [#467](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/pull/467) and [#469](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/pull/469); the isolated trial is draft [#461](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/pull/461). Each failed full attempt consumed its one-shot owner authorization. None of those failures proved a new mod was incompatible. The green fourth server run does **not** promote any updated version.

## Client/gameplay test matrix for the four-release trial

Use a new disposable world and record B/C evidence separately. **None of the tests below is implied to be passed by packaging or server smoke.**

| ID | Priority | In-world test and observable result |
| --- | --- | --- |
| CLIENT-1 | Critical | Import the GitHub Actions ZIP **directly into Prism**, not by extracting/re-zipping; confirm Minecraft 1.21.1, NeoForge 21.1.265, Java 21, packwiz download/verification, four first-party JARs, and a main-menu launch without mod-loading/mixin errors |
| CLIENT-2 | Critical | Create, enter, leave and rejoin a brand-new test world; no crash, missing registry, KubeJS server script errors or broken recipes at initialization; inspect latest.log |
| NEO-1 | High | Open/operate Neo Vitae Ara Vitae / Tabula, Athanor and ritual apparatus. Run one representative recipe or ritual, inspect EV/spiritus or resource draw, verify correct output and repeat after chunk unload/rejoin; leave idle Athanor running briefly for new idle behavior |
| EVIL-1 | High | Check EvilCraft blood capture/storage/transfer, inventory item interactions and a representative blood-powered craft; validate JEI/guide recipes and display stands without item loss/duplication |
| BLOOD-1 | High | Test the TMM **EvilCraft-canonical blood** compatibility with JAWR/Hexerei where present; verify blood containers and related recipes behave with the revised EvilCraft version and do not break vampire healing or food/diet rules |
| GOETY-1 | High | In a **new** world, find at least one Goety mob/structure in an intended biome and try core spell/summon behavior; exercise a summon through combat, owner death or relog as appropriate; check for worldgen conflicts with Tectonic/YUNG's mods |
| ARS-1 | Critical | Ars Elemental beta 0.7.11.3: confirm glyph/focus item visibility, spellbook crafting or setup and casting representative elemental spells, Ars Nouveau 5.13.5 integration, and mana cost; test a spell against an entity and block in survival |
| ARS-2 | Critical | Save/rejoin, repeat Ars Elemental spell use, then test on a hosted/local dedicated-server connection if available. Verify the beta's reported dedicated-server crash fix without assuming a single-player test proves it; inspect both logs |
| CROSS-1 | High | Exercise cross-mod recipe/tag/JEI visibility and any Neo Vitae/Ars/Goety/EvilCraft gameplay interaction you actually rely on. A newly broken recipe or missing registration is a blocker even if the game boots |
| REGRESSION-1 | High | Recheck one Monk or Hunter MXP action, JAWR transformation/blood, an FTB quest claim and inventory handling. This distinguishes a third-party update regression from unrelated integration work |
| SAVE-1 | Critical | Quit, relaunch, load the disposable world, verify no lost spell/ritual/quest/player state, then capture mod versions, logs and any reproducible errors |

**Pass gate:** no client startup crash, reproducible in-world regression or unexpected persistent data loss; no bad mod dependencies, severe recipe/JEI breakage or worldgen blockers. Log unresolved deviations individually, do not infer a green outcome from a smoke test. Test beta Ars Elemental separately; approval to *trial* 0.7.11.3 does **not** approve its integration as a production release.

## Boundaries and artifacts

- **Owner-only, one-shot:** each issue #291 command requires new consent and nonce. Source-only tests never start Minecraft. No automatic full smoke/Prism event is enabled.
- **Evidence:** [Actions artifacts from run #44984328474](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/actions/runs/44984328474) include hashes, Packwiz diff, provenance and logs; artifact retention is time-limited.
- **Prism trial:** use the successful `/tmm-update prism ...` run's specifically named experimental artifact, **not** the permanent `Too-Much-Magic-Unstable.zip`. Its manifest carries the isolated snapshot identity, prior server success and explicit beta hold.
- **Branch hygiene:** leave `test/full-integration` and the official release unchanged. Retain audit and rollback metadata; only the designated integration writer promotes reviewed changes, with separate owner decision for betas.
