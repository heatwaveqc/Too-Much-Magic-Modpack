# Monk compatibility: API verification and Elastic resolution

**Date:** 2026-11-14  
**Scope:** the ten *non-attribute / external-resource* Monk candidates in the 270-source catalog; Apotheosis 8.9.0 Elastic.  
**Verification level:** upstream **source-level inspection**, pinned-version identity cross-checked against packwiz. **No compiled addon, in-game test, or local pinned JAR symbol/ABI validation was performed.** Sources are the public 1.21.1 upstream branches and Mahou's official player/admin documentation; source branches may be ahead of or behind the exact pinned releases.

## Decided: only one Step Assist

[Apotheosis 1.21 branch Elastic JSON](https://github.com/Shadows-of-Fire/Apotheosis/blob/1.21/src/generated/resources/data/apotheosis/affixes/armor/attribute/elastic.json) defines **only** `minecraft:generic.step_height`, `add_value`, boots category:
- Common / uncommon: `+0.5`.
- Rare / epic: `+0.5..+1.5`, increments of `0.25`.
- Mythic: `+1.0..+2.0`, increments of `0.25`.

There is **no separate bounce, jump, cushioning or fall-damage mechanic** in Elastic's source definition. The Monk gets **exactly one native Step Assist** to traverse one-block obstacles. **Elastic is an archived/derived source alias, not a second purchase or a three-stage Monk skill**. Higher +step bonuses from item affixes are not included in Monk progression. The source catalog retains Elastic for audit and the provisional 204-endpoint count does not change because it was already aliased. Test collision and actual attainable step height.

## Implementation priority

1. **Low-friction source-backed adapters:** Roots player mana capacity and legal regen; Primal induced attunement; Occultism ownership-filtered familiar buffs and spirit modifiers.
2. **Re-scope before coding:** Primal proficiency -> Sorcery expertise-rate candidate (not spell damage); Astral Attunement -> optional perk XP or effectiveness (never another attunement); Roots 'Terra' -> actual Mana.
3. **Blocked by semantics/API proof:** Mahou Tsukai 1.36.31 exact player mana Java API / per-cast cost interception; Neo Vitae personal ritual-only attribution.
4. Once the first-party mod adapters are compiled and in-game verified, proceed to the distinct **55 Apotheosis event-affix** implementations. None should be treated as installed merely because a source bridge seems plausible.

### ABI, persistence, and integration tests still required

- Compile with the exact pinned NeoForge 1.21.1 dependency jars; verify branch APIs are present in the installed binary (especially Mahou, whose published project does not expose the Java sources inspected here).
- Server authoritative source/owner checks and data attachment survival across login/logout, death/clone, dimension change, game restart.
- Reconciliation when Tyz rank is refunded, prior stage is reduced, faction membership changed, or supported mods are removed/updated.
- Existing equipment and enchantment modifiers must not be double applied; avoid writing to vanilla or mod permanent research structures.
- No cross-player leakage when multiple Monks summon creatures, share altars, or work near another player's spawner/altar.
- Test server and Prism client with complete pinned modpack; no claims of gameplay verification before this.

**Verdict:** 4 candidates have source-backed direct/player-owned extension paths (Primal attunement, Roots mana, Occultism familiar and summon), 2 have demonstrated but still unverified Mahou implementation surfaces (capacity/regen), 2 need semantic redesign (Primal proficiency, Astral attunement), and 2 cannot safely work as proposed without a new hook (Mahou efficiency, Neo Vitae ritual mastery). All are still design-only.
