**Working source of truth for future entity-type decisions; development/integration reference, not a datapack or live configuration.** All 1,763 registered types from frozen #348, including non-creatures, are keyed by exact registry ID in [registry-v1.json](registry-v1.json). [registry-v1.schema.json](registry-v1.schema.json) defines the versioned structure. The earlier CSVs remain immutable evidence/checkpoints; cite the source path and exact ID, not duplicated prose. Future owner decisions should update the JSON, not start another parallel ledger. Update registry_revision on any content change, schema_version only for incompatible format changes. Keep native verification and provisional status separate from owner decisions. New/removed IDs require reconciliation against the next frozen installed census and report of changes; never silently carry stale IDs into generated tags.

## Field contract
- name/category: observed registered display name and category, not a biological or combat assertion.
- taxonomy: current working families (case-preserved approved vocabulary), other_categories (e.g. Humanoid), identity and exact source review status. Empty families with unreviewed/family_review is not a final absence of family. No automatic family-driven prey or harvesting rule. Family tags remain a separate integration task; do not activate this working taxonomy without review.
- hunter.prey: allow, deny, or hold. Explicit allow only; deny overrides, hold absent/closed. Tame/player/owner and exact damage attribution guards remain in Progression. Familiars, enemy uses and provisional technical exclusions retain shared native QA; this import does not settle them.
- capture.disposition: exact shared added-denial/hold/exception/native-pending disposition from boss-capture ledger. blacklist_target and approved_misc_default_deny are proposed pack-added denials for Capturing, Reliquary charms, alternate spawn eggs and relevant duplication routes, not proof of effective native policy. native_policy_pending and approved_vanilla_exception carry no added type denial, not force allow. review_hold is unresolved, not a permission. Native denials remain authoritative; item/variant mapping must be checked. egg_evidence records only actual prior evidence, not an egg whitelist. No generator for capture until owner/consumer-specific activation review. Sentry Watcher custom placement preserved.
- boss.classification and boss.credit: independent authored encounter candidate/derivative/hold and credit policy; not a Hunter XP multiplier, not a deployed boss event adapter. Instance rules distinguish Foreman and ordinary Doloris, augmented Null Servant, group fights and passive conversions. These are declarative requirements, not executable discriminators. Do not infer instance identity from HP or type ID.
- resources: independent per-entity overrides (when researched) for living, blood, Malum and Primal Magick. Currently all inherit defaults: living unverified, three resource mechanics unreviewed. Missing override is never an allow/deny. Future numeric yield or affinity semantics require explicit schema extension and separately approved native adapters; no fabricated values.
- misc: existing shared MISC disposition where applicable. native_verification defaults pending; sources record immutable prior CSV provenance by entity ID, which retain exact evidence/notes/holds. No claim of live verification.
