Decree objective/reward pool sets, canSpawn/canReveal/canWanderBuy; pool exact item delivery and entity kill, command reward and configurable mixing. Exact binary audit first. - Read-only targeted CI downloads two exact upstream candidates, verifies provider SHA512/SHA1 against actual bytes, inventories JAR metadata and default pools/decrees, recipes/loot/worldgen paths. No JARs uploaded or committed; report metadata only. Verify license discrepancy, required dependencies, cloth config and Kotlin for Forge 5.12.0 closure from report; pin only after review by integration writer.
- Compiler creates isolated native config files and localization from an audited/reviewed registry and effective EMC input. Requires explicit allowed item-barter settlement (proposed fallback, not owner-approved) and matching candidate hash. Each decree has exactly one reward and one input, fixed quantities; each input's EMC must cover payout. No command/coin rewards, entity kills or transformation pools yet; no claim to gameplay safety. No runtime output without reviewed inputs. This avoids inventing a coin-to-EMC exchange or trusting pre-mapping values.
