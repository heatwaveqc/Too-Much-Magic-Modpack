# Embers Re-Ignited 1.21.1-1.5.9 — personal powers, Pufferfish hooks, and magical engineering audit

**Reviewed:** 2026-11-13 (Phoenix local). **Source:** [Riieno/EmbersRekindled-Reignited at `82c263a`](https://github.com/Riieno/EmbersRekindled-Reignited/tree/82c263a2af72ef320ef2593a942586424f0026cf). Release metadata: [Modrinth 2r51o0lC](https://modrinth.com/mod/embers-re-ignited/version/2r51o0lC). **No separate bytecode inspection or actual mod-specific gameplay test was performed.** B6's previous 118-JAR dedicated-server smoke covers loading only.

## Executive answer

The user's recollection is substantially right: this mod is **principally stationary magical engineering**, processing, Ember production, alchemy, piping, refinery machinery, portable charge stores, and powerful equipment augments, **not** a book-and-spell caster with personal mana attributes. However it **does** have two player-fired magical weapons, persistent Ember-fueled tools and several player-active armor/weapon augments. Crucially, this exact version exposes **NeoForge hooks** for projectile construction and player Ember expenditure.

**Classification: Confirmed (source-backed hooks)** under the matrix definition, NOT gameplay-tested Pufferfish support. Recommend *small* Ember efficiency / attack / craftsmanship nodes under general magic & magical engineering rather than an entire bespoke spell-school tree. No distinct built-in registered player Ember mana/max/regen attributes were identified. Preserve Embers' **item and machine Ember**; do not join Ars+Iron's shared mana or Psi. Do not install Create to expose optional Create integrations.

## Real integration seams and their limitations

1. [`EmberRemoveEvent`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/api/event/EmberRemoveEvent.java): emitted by [`EmberInventoryUtil.removeEmber(Player, amount)`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/util/EmberInventoryUtil.java), gives `getPlayer()`, `setAmount(double)`, `addReduction(double)`, and `getFinal()`. Installed [discount baubles](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/item/EmberDiscountBaubleItem.java) already subscribe and accumulate reductions, clamped so final debit never negative. **Confirmed source API for a player-specific Pufferfish cost efficiency bridge.** Risks: (a) cost event covers *all player* expenditure, not just weapon spells; (b) cumulative reductions may reach **free usage** with native Curios + Pufferfish skill; (c) Cinder Staff and Blazing Ray (and several augments) check **pre-discount original** Ember reserves *before* calling remove, so discounts reduce actual spend but **do not lower minimum reserve to initiate a shot**. Test both and cap skill integration sensibly; **no balancing change authorized here**.
2. [`EmberProjectileEvent`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/api/event/EmberProjectileEvent.java): dispatched by both weapons before `IProjectilePreset.shoot()`. Provides `getShooter()`, `getStack()`, `getCharge()`, `getProjectiles()`; presets expose mutable `getEffect()/setEffect`, velocity/color, and `EffectDamage.setDamage`. Cinder Staff wraps damage in `EffectArea`, while Blazing Ray uses `EffectDamage` directly. **Source hook for ranged magic potency**, but exact safe access through `EffectArea` needs review, as does possible damage scaling from Pufferfish universal attributes; avoid double multiplication.
3. [`EmbersAPI`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/api/EmbersAPI.java) exposes stored Ember totals/capacity, removal, scales, equipment resonance registration and lens/hammer API. Useful for inspection and bounded item-specific enhancement; **no native player magic attribute**.
4. [`AugmentUtil`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/api/augment/AugmentUtil.java) can read installed augmentation and item heat/levels, with setter methods to mutate item-level quality. Prefer explicit creation/imprint hooks to arbitrary global boost; avoid bypassing forge cost, cap and native heat progression.
5. [`ScaleEvent`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/api/event/ScaleEvent.java) exists for defensive barrier interaction, but directly altering this for generic global defense could introduce unwanted multiplicative stacking.

**No first-party Pufferfish integration or Scriptor/Psi-like KubeJS event wrapper was verified**. A narrow NeoForge bridge is the safest known implementation path; KubeJS interop remains a hypothesis until runtime-checked.

## Magical infrastructure and energy economy

- Machinery dominates: Bedrock/Ember Bore, Ember Activator, copper cells/chargers, Ember injection/ejection, alchemy tablets, melters, stamps, refinery, mechanical cores, item/fluid transport and crystal-seed nugget growth. No player caster is needed for machine throughput, so generic `+spell power` should **not** silently affect these machines.
- **Important FE generator already included:** [`EmberEnergyConverterBlockEntity`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/blockentity/EmberEnergyConverterBlockEntity.java) converts **1 Ember → 100 FE**, at up to **1,000 FE/t per block** (an internal 20,000 FE buffer) with outward-facing energy capability; **Ember-to-FE only** in the audited method. *Theoretical* peak, not measured sustained Ember supply. Benchmark against **PsiTweaks' `trick_supply_fe`** and late Draconic demand before considering removal of BiggerReactors; a second magic-powered FE generator may be preferable.
- Re-Ignited advertises optional **Create** and **Sable** integration, but **Create is excluded from this pack**; neither install Create nor count Create mechanisms as currently available.
- The base Ember Bore produces only the *configured recipe* outputs under biome/height/structure/fuel requirements. It is not a general-purpose arbitrary ore generator in the inspected source.

### Most significant progression finding: crystal-seed renewability

- [`ConfigManager.ENABLE_DYNAMIC_METAL_SEEDS`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/ConfigManager.java) **defaults TRUE**. [`DynamicMetalSeeds`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/util/DynamicMetalSeeds.java) discovers metals tagged both `c:ingots/<metal>` and `c:nuggets/<metal>`, excluding already-defined stock seeds and a blacklist (default `netherite`). Requires all tag entries to exist in the loaded pack.
- [`DynamicMetalSeedAlchemyRecipe`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/recipe/DynamicMetalSeedAlchemyRecipe.java) requires **three ingots of the selected metal** on the alchemy pedestals, correct aspectus, and a crystal-seed tablet, rather than creating a new metal from nothing. Thereafter, the resulting seed can repeatedly produce that metal's **nuggets** by consuming Ember through an injector ([`CrystalSeedBlockEntity`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/blockentity/CrystalSeedBlockEntity.java)). Potential implication: **renewability after first 3 ingots** may impact late-game tech metals. This is not automatically a violation; evaluate gated first acquisition and economics.
- **Crucial exception:** `uranium` is an existing *static* `MetalCrystalSeed` in `RegistryManager`, so it is **excluded from dynamic seed discovery**. The repo includes an item and loot-table definition for `embers:uranium_crystal_seed` but **no stock uranium alchemy seed recipe found in the inspected source tree**. Thus the generic dynamic recipe does **not** by itself give an easy uranium factory. **Verify in actual pinned JAR and merged B6 datapacks** before concluding uranium is obtainable or impossible. Other `c:ingots/*` modded metals (e.g. potentially draconium, only if correctly tagged) still require a tag/recipe audit.
- A **targeted datapack blacklist** is supported through [`metal-seed-blacklist.json`](https://github.com/Riieno/EmbersRekindled-Reignited/blob/82c263a2af72ef320ef2593a942586424f0026cf/src/main/java/com/rekindled/embers/util/DynamicMetalSeedBlacklistReloadListener.java) under a datapack namespace, if a demonstrated late metal should stay gated. Prefer narrow exceptions to turning off an excellent magical resource-renewability system. **No blacklist or config change applied**.

## Recommendation / implementation order

1. **Confirmed** source integration seam. Give Embers a *small collection* of broadly applicable magic/equipment or artisan skill effects: bounded player Ember spending efficiency, Ember projectile effectiveness, and perhaps at-craft augmentation quality. **No need for a new full personal spell tree** in the first production pass.
2. Protect the mod's native progression: Ember item storage, heat, augments, Codex research and machine networks are not personal mana; avoid granting high heat/augment tiers just for selecting Pufferfish skills.
3. First pilot: an opt-in NeoForge `EmberRemoveEvent` handler for a simple skill-tagged player with 10% discount, test stacking with native Curios reduction and inability to fire below precheck threshold; and an independent projectile event diagnostic logging shooter, subtype, base damage and charge. No need to ship those in the current design audit.
4. Separate item-imprint prototype later if requested: one item quality tier at forge/first pickup; persistent via item data; test transfer, rollback and native augment caps. Don't quietly add generic machine buffs.
5. Test Embers **Ember→FE Dynamo** at sustained Ember supply (1,000 FE/t is block-side cap, not generator sustainability). Evaluate against Psi FE + Draconic transfer. Measure total production and upstream feed cost.
6. Run a B6 **merged-tag audit** for `c:ingots/*` and `c:nuggets/*` exposed by other mods, including technical resource gates. Verify whether a static uranium seed is obtainable and whether dynamically discovered high-tier metals are desirable renewability after first obtaining 3 ingots.
7. Version-specific gameplay to validate: weapon damage, Ember consumption, projectile hook server/client ordering, Curios discounts, blast mining/power, armor scales attachment, mixed forge augments, server performance and optional Create code inactivity.

**No mods, config, progression gates, item tags or packwiz entries were changed during this audit.**
