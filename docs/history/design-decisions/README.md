# TMM Design History Archive

These files preserve superseded and historical issue bodies **for provenance, not implementation authority**. Engineers and scheduled agents must use the **current GitHub issue body**, current approved PRs, exact integrated source, and repository policy before coding. Historical snapshots can contain explicitly withdrawn goals, stale numerical values, unmerged implementation plans, or claims invalidated by later integration.

## Archival contract
1. Save the exact issue body in an immutable reviewable Git snapshot *before* changing the live issue.
2. Document the issue number, capture date, original `updated_at`, decision chronology, currently authoritative links, and known supersessions.
3. Merge and verify archival references before altering the issue. Re-fetch the live issue immediately before editing and require byte-for-byte agreement with the archived snapshot; abandon the edit on any intervening changes.
4. An edited issue should retain its current owner-approved scope, code-ready work, genuine undecided design questions, in-game QA, cross-PR ownership and source status. Do not equate source-ready or pinned with gameplay acceptance.
5. An archive is not a branch-retirement manifest, permission to delete refs or issues, or authorization for a full modpack build.
6. A snapshot is an exact historical record, and must not be modified to incorporate later conclusions; put clarifying context into a separate chronology.
