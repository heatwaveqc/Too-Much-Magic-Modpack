## Skillet adapter target
Reference FD https://github.com/vectorwing/FarmersDelight/blob/1.21/src/main/java/vectorwing/farmersdelight/common/block/entity/SkilletBlockEntity.java and CFB https://github.com/TwelveIterations/CookingForBlockheads/tree/1.21.1 .
FD skillet has a single slot, uses CAMPFIRE_COOKING and drops cooked output normally. Its addItemToCook(ItemStack, Player) validates recipe/waterlogged/empty state, inserts, calls native timing initialization including Fire Aspect, and returns remainder. Raw inventory insertion alone skips timing initialization. Implement minimal player-aware server-side CFB processor/recipe handler or supported native API, no mixin if avoidable; do not register as a generic source or bypass heat. Validate exact pinned APIs. Check recipe availability, actual player and target, preflight obstruction, consume a token only when safe, pass stack to native method, restore rejected remainder exactly once, never spawn result manually. Preserve oven and cooking pot; if CFB's processor interface lacks player context, investigate supported context instead of passing null. Food-only recipes, no general smelting route. Keep native output-drop behavior. If CFB already supports skillet in pinned jar, prefer it.
