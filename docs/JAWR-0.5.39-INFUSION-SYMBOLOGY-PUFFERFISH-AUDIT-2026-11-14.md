# Just Another Witchery Remake 0.5.39 — Pufferfish infusion, Symbology and ritual audit

**Date:** 2026-11-14, Phoenix local. **Pinned:** `witchery-0.5.39+mc1.21.1` NeoForge, published 2026-11-09 as [CurseForge file 9525978](https://www.curseforge.com/minecraft/mc-mods/just-another-witchery-remake/files/9525978) / [Modrinth version TWcJbsjg](https://modpacks.ch/mods/minecraft/LCO8KZvC/just-another-witchery-remake/versions/TWcJbsjg). **Scope: NON-TRANSFORMATION magic only.** Death, lichdom, phylacteries, vampires, lycanthropy, dragon and abomination/hunter states belong to the **separate Transformation Compat mod**. Not a revived requirement for this skill investigation.

**Result:** **Compatible with work**, rather than Needs Investigation or Nothing separate: JAWR has genuine **personal infusion charge** and **Symbology player spellcasting**, whereas its physical altars, brews and rites are not naturally improved by player attributes. The direct Pufferfish→infusion bridge **is not confirmed** and **no native NeoForge player attribute IDs** for infusion charge or spell potency have been established. This is a technical opportunity to evaluate, *not a locked user decision to implement a bridge or standalone JAWR skill tree*.

## Sources and confidence boundaries

1. **Author's [Witchery issue/research repository README](https://github.com/mrsterner/witchery-issues/blob/main/README.md)** gives public, official, current schema for `witchery:ritual`, `altar_power`, `altar_power_per_second`, ordered `ritual_events` (requirements, outputs and neutral events), `run_command` contextual placeholders (`{owner}`, `{witchPower}`, `{taglockPlayer}`, etc.), `min_witch_power` and `max_witch_power`, nature-provided altar power, augment categories and **`overworld_infusion` ore extraction recipe** (default 100 personal infusion charge to produce two specified items from a mapped ore block, replacing the block).
2. **Confirmed current version family, dated issue [#129](https://github.com/mrsterner/witchery-issues/issues/129)**: user reports `Rite of Charge Infusion` in **0.5.39/MC 1.21.1**, showing recharge mechanic exists in this version (but not validating the reported Stackable Potions incompatibility in our pack).
3. **Dated issue [#118](https://github.com/mrsterner/witchery-issues/issues/118)**: 0.5.36/MC1.21.1 player suggestion explicitly references live **Symbology** spells `Kindle` and `Water Conjure`; evidence of *direct player casting* outside vampire/lycan abilities (not necessarily all symbols of original 1.7.10 Witchery).
4. **Source of player-native infrastructure from a secondary third-party guidebook extraction**: [PiglinMine JAWR item's embedded Guidebook section: Hobgoblin](https://piglinmine.com/item/witchery/gulgs_gurdle?server=mod) says Hobgoblin worshippers can recharge *player infusion power* and expand **Symbology grid**. That is **native progression**; Pufferfish should not duplicate/reduce the significance of the worshipper system. This site isn't a pinned 1.21.1 binary audit; confirm in game before using numeric thresholds.
5. [0.5.39 CurseForge changelog](https://www.curseforge.com/minecraft/mc-mods/just-another-witchery-remake/files/9525978): cauldron and Lilith fixes; not a stat/attribute API document.
6. **Not obtained or examined:** exact 0.5.39 JAR bytecode, `Modonomicon` runtime book content in the deployed version, source from upstream `mrsterner/witchery` implementation (not public in repository discovery). Original Witchery 1.7.10 wiki articles describe *historical* mechanics, **not evidence that every old Infusion/Symbology spell exists in JAWR 0.5.39**. Do not port old abilities or numerical costs into implementation based only on that wiki.

## Potential Pufferfish nodes — design candidates only, not authorized

1. **Infusion discipline:** small bonus to active personal infusion charge **efficiency or capacity**, preserving dedicated Witchery recharge. This would meaningfully enhance direct casting, unlike altar-power discounts. Source-level hooks not confirmed; select **one** to avoid stacking huge bonuses. Bounded efficiency so abilities cannot reach zero cost; native Hobgoblin worshipper recharge/grid rewards remain useful.
2. **Symbology mastery:** scale applicable spell strength, range/duration or a *small* personal cost reduction, sharing a generic magic/proficiency branch where practical. A directly attributable server cast and item-level dispatch hook would be necessary. Do not invent a blanket damage stat if effects spawn vanilla water, place fire, or run commands.
3. **Generic ritual feat (optional, lower priority):** author-provided JSON `run_command` can execute commands using `{owner}` and `{witchPower}`, so a new skill-sensitive rite could potentially use an exposed Pufferfish scoreboard/command condition without changing code. But it would require designing new rites instead of improving the original ones; **not a recommendation to do so now**.
4. **No parallel mana:** personal Witchery **infusion charge must stay distinct** from Ars Nouveau/Iron's shared mana, Psi, Hex media, Embers, Goety soul/Arca and the physical nature altar. These resource systems have different acquisition and advancement mechanics.
5. **Don't duplicate natural Witchery unlocks:** If creature worship already expands the Symbology grid and refills charge, a permanent Pufferfish grid-size or recharge bonus may undercut that progression. The strongest options are **efficiency / tailored cast potency**, not replicating the native source of recharge.

## Potential inter-mod resource-gate overlap (not a skills blocker)

- JAWR's documented `overworld_infusion` metal extraction turns **existing permitted blocks** into two outputs, replacing the block. Like Enchanted's Transpose Iron, it is not general infinite ore generation by default.
- Review the **merged 1.21.1 JSON map** for entries targeting first-access tech ore (uranium, draconic dust, replication ore) or costly endgame ingots before introducing craft/loot gates; **do not assume stock JEI entries bypass restrictions** and do not nerf useful automation without a demonstrated leak.
- Ritual `mine_blocks_below` also targets **specified** ore IDs; data-driven rites could mine forbidden resources if we ourselves add such a rite.
- Author lists **`has_infinity_egg`** as a powerful altar augment (10× power multiplier and 2× capacity boost). This is already native progression: don't blindly add a Pufferfish altar-power multiplier over it.
- A [reported 0.5.39 cauldron issue on 26.1.2](https://github.com/mrsterner/witchery-issues/issues/127) may involve recipes completing without declared altar power. Test actual pinned 1.21.1 before calling it a bypass or altering balance.

## Proof-of-concept tests required before implementation

A. **Player infusion mechanics**: in copied B6 Prism client, obtain infusion; record UI charge, activate Overworld ore extraction, note precisely which ore tags are accepted and charge debit (100 expected), recharge via `Rite of Charge Infusion`, restart and inspect persistence. Determine whether capacity, charge and per-ability costs appear in public attributes vs own attachment/capability/saved data.
B. **Symbology cast**: verify current 0.5.39 availability of Kindle and Water Conjure; inspect their actual cost and effect, spell list and grid UI, mouse/key dispatch, server-side attribution and data persistence.
C. **Native long-term progression**: test Hobgoblin worshipper recharge and Symbology grid expansion; confirm it doesn't become redundant if a small universal Pufferfish buff is added.
D. **Pufferfish pilot**: temporary 10% nonzero infusion cost discount on ONE personal cast, or modest applicable cast potency, only after identifying a reliable cast hook. Make sure it doesn't apply to altar power, other players, infused items or offline machinery; remove temporary test modifier and test respec/logout/dimension/other hybrid forms. **If the hook is disproportionate, close as no dedicated skills.**
E. **Cross-mod tests limited to Pufferfish**: sample standard magic-damage attribute impact on one actual JAWR spell; verify any action-specific immunity, item projectile damage or ticking spell. Death/lich/vamp/wolf/dragon state tests are **not part of Pufferfish** and should be handed off to Transformation Compat.
F. **Ritual economy and data**: ensure any custom rite/brew remains attractive at native costs; inspect Witch Power branching and the precise effect of cat/coven; no blanket buffs to nature altar or all brews.

## Classification and decision

**Move from Needs Investigation → Compatible with Work**: We have enough evidence to identify a *meaningful target* (personal infusion charge and Symbology spells), but no direct code bridge or runtime-proven Pufferfish attribute. Pufferfish delivery remains deferred until exact hook discovery and one minimal pilot; **user has not yet approved implementation**. Avoid parallel independent JAWR skill tree if general magic skill nodes can be shared. Transformations and death effects remain outside this entire study.

**No JAR unpacked, no bytecode inspected, no runtime test, no code branch, no skill tree or config changed.**
