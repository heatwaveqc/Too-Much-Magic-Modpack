# QA execution types — A / B / C (owner standard, 2026-11-17)

Use this standard for **every** test-build handoff. It complements, rather than replaces, the [eight canonical testing levels](TEST-LEVELS-AND-TERMINOLOGY.md). Execution type says **who/how to test**, not what runtime evidence already exists.

| Type | Name | Required procedure | Evidence boundary |
| --- | --- | --- | --- |
| A | **Codex / automated offline** | Read exact installed snapshot, manifests, configs, code, JAR/ZIP contents, already-produced logs and read-only copied saves. Use local non-game validators, fixture tests or compile/unit tests where needed. No Minecraft process, live commands, live-save writes, donor assembly or new build. | Source/artifact/log evidence only; no new in-game behavior certified. |
| B | **In-game command tests** | In the existing authorized disposable world, exact paste-ready commands in order, specifying player/OP, starting mode, preparation, expected output/state and cleanup. Brief physical actions (drink/use, hit, inspect immediate chat) are fine when commands supply nearly all setup. | Actual runtime evidence; not a full survival or client UI pass. |
| C | **In-game play/setup tests** | Anything needing meaningful manual interaction, structures/rigs, crafting/brewing, visual/UI checks, natural AI/spawns, travel/exploration, death anchors, repeated trials, world reload or multiple players. Commands may prepare the setup but do not replace the real behavior. | Named mechanic/player evidence only. |

A runs first; assign B/C to the player after reporting blockers. Include test IDs, exact installed build/frozen source SHA, commands or file paths, expected outcomes, status and evidence. Break a larger feature into A/B/C subcases rather than calling an entire feature automated. Preserve earlier accepted tests; retest only affected behavior or dependencies, and link historical evidence. Separate inclusion readiness/owner deferrals from test status. No invented commands, IDs or permissions: verify custom command registration and the exact pinned mod documentation/config where available; otherwise explicitly flag missing or unverified syntax, and do not assign a fake command. Commands belong in fenced blocks or inline code, without prompt/comment characters; replace named placeholders before execution. Operator-only QA fixtures are not proof of natural acquisition, normal permissions, or gameplay.

Record PASS/FAIL/PARTIAL/BLOCKED/NOT BUILT/NOT RUN and observed output or log path. A completed green server smoke/package may be read as existing evidence in A but is not A authorization to start another server. A new build, full smoke, client launch or live world manipulation still requires the applicable explicit authorization. Maintain a per-build checklist and results ledger linked from the QA hub; update canonical feature acceptance only from matching evidence, via the existing registry workflow. Do not commit private player information, worlds, mod JARs, full logs or credentials.
