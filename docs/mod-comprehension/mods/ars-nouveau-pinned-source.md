## Build a first working supply

Open Worn Notebook → **Getting Started → Source**, then **Source → Source Jar / Agronomic Sourcelink / Mycelial Sourcelink**. Native Documentation.initOnWorldReload registers all five links and five Source relays in Source; the Dominion Wand entry is in **Crafting**, cross-linked from relay entries. Use those named entries and JEI, not a Patchouli book requirement.

1. Craft Source Jar (six Archwood Slabs and two glass-block-tag items, grid below) and Agronomic Sourcelink (two Source Gems, two Gold Ingots, Wheat). Place jar within five blocks on each axis of link; adjacent is the clearest first setup.
2. Grow crops naturally within link's event distance15; ordinary CropGrowEvent.Post gives20 Source, native magic-plant-tag growth45. Link registers in the event queue on120tick boundaries; first instant growth immediately after placement may precede registration. Tree success is a different event, not every sapling placement.
3. Link buffers Source, and on100tick boundaries sends to the first acceptable nearby provider. Jar is10000capacity. Observe jar fullness, then run a consumer such as a ritual with a documented Source request. An empty jar or crafted link alone does not prove generation or spending.
4. Food-driven alternative: use Mycelial with eligible food dropped close to it or on a surrounding Arcane Pedestal; it consumes input and may waste excess at a nearly full buffer. Collect crafting remainders and keep unintended foods away. Sourcelink recipes are alternatives, not five mandatory progression tiers.

## Storage and search contracts

Exact `common/capability/SourceStorage`, `api/source/AbstractSourceMachine`, `SourceManager`, `SourceProvider`, and `api/util/SourceUtil`:

- Jar capacity/receive/extract ceiling10000. Ordinary Sourcelink internal capacity20000, nominal maxReceive/maxExtract10000; its anonymous storage overrides **canReceive=false**. Native generation uses AbstractSourceMachine.addSource(int), which directly clamps stored total and bypasses the receive capability. Thus a producer can generate while refusing external capability injection. Source is neither FE nor potion fluid nor personal casting mana.
- SourceUtil ordinary-jar searches iterate BlockPos.withinManhattan with extent range on **each axis**, requiring loaded SourceJarTile; there is no additional spherical-distance filter in that branch. Special providers from SourceManager use closerThan(range), a separate strict-distance contract. Do not turn ritual range6 or link output5 into one universal spherical search rule.
- Sourcelink sends on100tick boundaries when nonempty to first SourceUtil.canGiveSource(range5) result, using source/target limits. Ordinary links use transfer ceiling10000. Unloaded jars are skipped; no chunk loader is provided by these calls.
- takeSourceMultiple can debit several providers; on insufficiency it adds extracted amounts back and returns null. A Creative Source Jar also refunds preceding debits, but is not a survival acquisition route. Particle helpers run only after a nonnull result. Third-party providers with unusual add/remove semantics require their own audit before claiming transaction guarantees.
- Direct add/remove return stored total, whereas capability receive/extract return actual transferred amount. Capability transfer simulates extraction and reception then commits the accepted quantity; legacy tile transfer computes min(transfer ceiling, available, free space). Mixing those return semantics gives incorrect rates.
- Source/count/color save to NBT; item components can retain block fill amount. Actual break/drop retention still depends on block/loot behavior and is not independently proven by a component serializer alone. Jar display percentage is integer division and fill state is quantized, not a precise throughput meter.

## Five producer choices

Evidence: exact five `common/block/tile/*SourcelinkTile` classes and `api/source/SourcelinkEventQueue`. Ordinary event range is distance helper<=15; Vitalic's timed baby scan instead uses AABB inflate15. Event routing is per dimension, loaded exact-class match, first eligible nonfull link only, then breaks; multiple overlapping links do **not** each receive a copy from this queue. World-set iteration is not a user-defined priority order. Registration every120ticks, not per-event placement discovery.

**Alchemical empty-buffer restriction:** tick condition is `(source>0 && canAcceptSource(source)) || getSource()<=0`. The typed canAcceptSource(int) delegates to SourceStorage.receiveSource(...,true)>0, which returns0 because Sourcelink storage canReceive=false (confirmed with javap). In the inspected default classes it therefore consumes only when its Source buffer is empty; it can consume again after output fully drains. Do not claim it continuously tops off a partially filled link, or that canAcceptSource(int) means enough room for the entire potion value. Initial no-argument capacity check and later typed check are different methods. This code finding requires a positive/partial-buffer runtime case before relying on it for automation.

**Side effects and false fuel counters:** Mycelial getSourceValue increments progress1, or5 for magic food; randomTick can spend progress>10 for a nearby mushroom on Mycelium (minus10), and>=25 for Dirt/Grass one below in3×3 into Mycelium. Volcanic getSourceValue mutates progress from fuel classification, and canConsumeEntireItem calls getSourceValue **again**. Accepted/skipped candidates can increment more than once before any debit, so this counter is not an audited count of consumed fuels. Random block tick spends150progress on Stone/stones-tag→Magma, or200 on Magma→Lava, in3×3 one below. Random ticks are separate from20/40tick producer cadence. These are prospective resource-loop risks, not an approved free-lava farm or measured renewable output.

Native tag payloads: `ars_nouveau:magic_saplings` contains four red/blue/green/purple Archwood saplings. `magic_plants` includes that tag plus Sourceberry Bush, Magebloom Crop, Frostaya/Mendosteen/Bastion/Bombegranate Pods. Item `magic_food` includes Source Berry Pie and Source Berry Roll. Other installed datapacks may extend/replace these tags; native membership is not an effective-pack whitelist.

## Route Source with the Dominion Wand

Craft the wand through Enchanting Apparatus (Stick reagent, two Source Gems and one Gold Ingot on pedestals, SourceCost0), then use Notebook **Source → Source Relay** and its related relay pages. Apparatus construction/activation is a separate parent crafting stage, not an ordinary crafting-grid wand recipe.

In the normal two-block workflow, wand selects first block, then invokes first/last connection callbacks on second use and clears selection. **Source jar → relay** makes the relay take from that jar; **relay → destination** sets where it sends. Same-world loaded endpoints are the supported teaching case. Shift-use a wandable with no stored data clears its connections; radial Clear/Normal/Strict controls are separate wand modes, and Strict stores a face. Avoid a stale selection before resetting links. Recipe/particles alone do not prove successful transfer; inspect Source decreasing/increasing at actual endpoints.

| Relay | Operation and limit |
| --- | --- |
| Ordinary Source Relay | Buffer1000, receive/extract1000; max distance30, rejects self. Every20ticks, if not disabled, pulls from loaded fromPos then sends to loaded toPos. Invalid loaded endpoint clears that link and returns; unloaded endpoint stays stored/skipped. Relay-as-source cannot be assigned through last callback; chain by first relay→next relay instead. |
| Collector | Runs inherited pull/send first, then scans range5 SourceUtil providers and fills local buffer. Excludes configured endpoints. Since collection follows inherited send, newly collected Source may wait for the next cycle. |
| Deposit | Runs inherited pull/send first, then distributes local remaining Source to acceptable range5 providers, excluding configured endpoints and RelayTile destinations in this local scan. Not unrestricted item logistics. |
| Splitter | Buffer2500, transfer2500. Lists of sources/destinations; every20ticks requires **nonempty destination list** before even pulling. Splits pull ceiling by eligible-source count, then current buffer by eligible-destination count using integer division; zero share skips. Actual acceptance and list order can prevent perfect equality. |
| Warp | Inherits Splitter lists/buffer. closeEnough permits another RelayWarpTile beyond ordinary30, in the same world's BlockPos system; no dimension key in endpoint lists. Both ends must be loaded. Legacy tile three-argument transfer to Warp computes loss chance(distance-30)/100 above30, and on that branch removes full transfer but delivers max(1,floor(0.7×transfer)). At>=130 chance always succeeds. **Capability split paths call a different three-argument ISourceCap overload**, which this subclass does not override; do not assert every connection gets the same loss. The subclass's two-argument capability overload also has fallthrough after its attempted loss. Exact effective capability registration/path needs runtime audit, not a blanket lossless-distance promise. |

Redstone Relay is an automation device with a separate profile gap; it is not another of the five Source relay variants above. Brazier Relay redirects ritual position/inventory and uses its own16connection rule, detailed in [rituals](ars-nouveau-pinned-rituals.md).
