## Acquisition and inscription

Optional equipment after Apparatus. Notebook **Spell Casting** entries for Sword/Shield/Mirror, **Items** entries for Gauntlet/Fishing Rod, plus **Crafting -> Scribe's Table -> Scribing**; JEI exact item recipes. All five acquisition recipes are Apparatus, SourceCost0, one output. Tag names/quantities below are native inputs; effective pack tag members require JEI.

For Sword, Mirror, Gauntlet and Rod, create an **effects/augments-only** spell in the held Book (no Touch, Self, Projectile or any AbstractCastMethod), put tool on Scribes Table, select the desired composition, then sneak-use Book on table. Their isScribedSpellValid checks that *none* of the supplied parts is a cast method; handler prepends Touch for Sword/Gauntlet/Rod or Self for Mirror. A complete ordinary Touch spell is therefore the wrong inscription input. Native Mirror example Heal -> Amplify and Sword example Ignite -> Extend Time illustrate this. Shield isn't ICasterTool in inspected class and is not part of this inscription procedure. Generic successful scribing/data presence is not evidence the tool operated.

ICasterTool also accepts Spell Parchment as source and has Manipulation Essence hidden-recipe path. Shared handler can copy flavor/name/particles before final validation; don't treat a rejected inscription as proof every cosmetic field stayed unchanged. keepNbt=true is the apparatus contract, not blanket proof arbitrary invalid reagent component combinations are safe.

Sword and Shield inventoryTick call RepairingPerk.attemptRepair even when not selected. Its default periodic personal-mana repair and eligibility are traced in armor companion; this is active inventory upkeep, not free durability or requirement that a matching armor thread is fitted. Other tool classes above don't invoke that repair helper in their inspected inventoryTick. Gauntlet/Rod constructor no maximum-damage declaration means a hurtAndBreak call alone isn't proof of actual wear on default native item; effective components/enchantments need acceptance.

EnchantedHook's four-argument constructor receives luck/lureSpeed but calls FishingHook(entityType,level) without forwarding either; the inspected body never assigns those parameters. Rod computes enchantment luck/time bonuses before construction, yet that handoff alone doesn't prove they affect fishing. Treat enchantment effectiveness as an explicit test, not established from calculation. Hook context snapshots spell at cast; castSpell later passes owner's **current main-hand item** and MAIN_HAND, so offhand use/item switching deserves separate tests. These observations are native implementation boundaries, not permission for duplication or protected-target bypass.

Nonplayer sword path also has registered LivingDamageEvent.Post handler: when damage source entity is nonplayer living, holds Enchanter Sword main hand and distance<3, calls sword hurtEnemy. That callback uses EntitySpellResolver rather than ordinary player resolver; no claim every summoned entity pays player mana. Attribution, recursive spell events and protected entities require runtime review before recommending helper combat loops.

## Quest and acceptance handoff

Offer separate optional choices after Apparatus rather than demand every tool. Teach effects-only inscription -> tool injects form -> actual trigger. A crafted Sword/Mirror/Rod criterion proves acquisition only, not hit/self spell/hooked-target operation. Shield operation needs observed block event and temporary effects. Reward XP and modest ordinary repair/building supplies; don't award mana/durability loops without effective-pack review.

Unrun acceptance: valid effects-only versus rejected full-form inscription for each caster, actual target effect and personal mana delta, insufficient mana/canceled cast versus physical sword wear, Mirror duration/cost modifiers, Shield positive/zero block events plus buff expiry and repair. For Gauntlet, test one correctly tiered and one above-tier block with counted drops plus declared DIG versus transform actions. For Rod compare ordinary retrieve versus hooked spell/repeated use, luck/lure enchantments, offhand and held-item switch, full inventory fishing output and no-mana attempts. Include nonplayer sword callback/claims only in authorized disposable world. No live PASS or exploit-safe economy is established.
