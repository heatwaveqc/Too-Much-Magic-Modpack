## Camera route and guide references

Notebook **Crafting -> Scryer's Crystal**, **Scryer's Scroll**, **Scryer's Oculus**; **Spell Casting -> Enchanter's Eye**. Documentation links these four. Camera viewing and remote casting are separate actions. Ritual of Scrying is a separate ore-highlighting system covered in [rituals](ars-nouveau-pinned-rituals.md), not the camera prerequisite.

1. Craft one `scryers_crystal`: Eye of Ender + `c:gems/source`, shapeless. Place facing chosen view (placement uses clicked face). Empty main-hand interaction mounts its camera. Native prose's generic right-click instruction omits this empty-hand/main-hand condition.
2. Use Blank Parchment on Crystal server-side. Makes one `scryer_scroll` storing GlobalPos; adds to inventory or drops at player when insertion fails, then consumes one parchment unless infinite-material player. Parchment recipe is Paper surrounded by eight Magebloom Fiber. This creation is a world interaction, not a shapeless Scroll recipe.
3. Existing Scroll use on any ICameraMountable overwrites its GlobalPos without spending the scroll in inspected method. Name it for recognition. `scry_to_blank_parchment` recrafts fresh Blank Parchment and loses saved location.
4. Build Oculus with Apparatus: Eye of Ender reagent; Observer, Spyglass, Source-block-tag item and Diamond-gem-tag item on pedestals; SourceCost0, keepNbt=false. Place Arcane Pedestals around it, each holding a recorded Scroll. Client scans inclusive +/-3 on X/Y/Z (7cube); menu lists all Scroll stacks found, named by hover text. It doesn't prove each destination remains valid.
5. Interact Oculus main hand and select named Scroll from radial menu. Empty/no-position entries report failure; unloaded/removed camera reports native not-loaded message. Keep destination chunk loaded before access. The initial lookup must resolve a mountable block entity before the camera starts forcing chunks; mount-time tickets do not prove an arbitrary distant unloaded camera can bootstrap itself.
6. Movement keys pan/tilt the fixed camera; Shift/sneak key sends dismount. These are configured Minecraft keys, not guaranteed literal WASD. CameraController applies orientation limits by crystal facing; cameraSpeed3.3 times zoomAmount per relevant tick is a code step, not measured viewing speed. Test actual controls, exit, body vulnerability and multiplayer behavior separately.

**Dimension boundary:** Scroll stores GlobalPos, but Oculus sends **only BlockPos** in PacketMountCamera; server looks in `player.level`. It does not use saved dimension. Therefore do not promise cross-dimensional remote viewing; same coordinates in another world can select a different local mountable. This is a coordinate identity limitation, not a legitimate route around dimension gates.

## Viewing state, costs and loading

ICameraMountable creates a ScryerCamera entity at Crystal, changes ServerPlayer.camera and sends view packet; client switches first person and refreshes rendering. The player entity is not teleported by this method. Existing camera is discarded when switching. Server view distance is requestedViewDistance clamped between2 and server view distance; mount forces a square of `(2d+1)^2` chunks around camera with ticking flag false. Camera removal releases tickets in corresponding square. Runtime permissions, other chunk loaders, disconnect/death/reload cleanup and actual load/traffic impact remain acceptance tasks.

No Source, personal mana, durability or Scroll debit occurs in these inspected mount/menu methods. This is not proof of cost-free behavior under every addon/config/event. Crystal tracks playersViewing, sets `being_viewed` state on start/stop, and exposes raw count as comparator output. It is occupancy information, not an operation receipt for any spell or inventory transfer. Camera server tick discards if its block position no longer holds registered Crystal; verify user view restoration on removal rather than infer it from discard alone.

## Enchanter's Eye: cast from a camera location

Actual registered ID `ars_nouveau:enchanters_eye` (class/field ScryCaster/SCRY_CASTER). Apparatus recipe `enchanters_eye`: Scryer's Crystal reagent, four Blaze Powder and four Ender-pearl-tag pedestal ingredients; SourceCost0, keepNbtOfReagent=true. Stacks1, default ScryCasterData and empty position component. No requirement to have Oculus or its viewing session open appears in casting path.

Place Eye on Scribes Table and scribe selected spell from held Spell Book or Spell Parchment by selecting the desired spell in the held book, then **sneak-use the book on the table** (Notebook Scribe's Table/Scribing). Shared validator accepts syntactically valid spell; **casting** separately requires a cast method in BasicSpellTurret.TURRET_BEHAVIOR_MAP. Native map has Projectile and Touch; Self/other unsupported forms produce invalid-behavior message. Do not equate successful inscription with a working Eye spell.

Use Eye on Crystal to bind location, or hold recorded Scryer's Scroll in offhand to override bound Eye destination. Any offhand ScryerScroll wins, even one with empty location: it yields no-position instead of falling back to Eye. Server uses GlobalPos.pos only, **not its dimension**, then checks current world's isLoaded and block instanceof ScryerCrystal before canCast. These failures return before the explicit mana debit in this method. Eye itself doesn't force target chunks in inspected cast method.

Actual player is wrapped as PlayerCaster, not a turret TileCaster; personal mana/validation apply. Facing comes from Crystal, not remote player's look direction. Projectile uses rear-offset ScryerCrystal dispense position and fixed facing vector. Touch operates on adjacent facing block, choosing a random living entity in its block AABB when any exist; otherwise uses block hit. It is not arbitrary remote crosshair targeting.

**Debit order is significant:** after initial canCast, ScryCasterData calls mapped behavior then **unconditionally calls resolver.expendMana()**. Projectile behavior constructs/spawns projectile directly, with that explicit debit afterward. Touch behavior calls resolver.onCastOnEntity/onCastOnBlock; those methods recheck canCast/events and, on CastResolveType.SUCCESS, call expendMana internally, before the Eye's outer unconditional call. Thus successful Touch has **two native debit calls**, while a rejected/canceled inner Touch may still reach the outer one after initial precheck passed. No guard marking already-expended appears in inspected SpellResolver.expendMana. Each call recalculates expended cost/events; do not promise exactly twice a displayed number under modifiers. This differs from Source-prepaid turret behavior, whose TileCaster type bypasses expendMana. Count mana deltas and cancellation boundaries in acceptance; no generic refund, hit guarantee or atomic operation result is proved by dispatch.

## Registration boundaries and quest handoff

Old `ScryerPlanarium` and tile classes are present, but inspected BlockRegistry registers real Planarium/PlanariumProjector instead; no ScryerPlanarium registration there. Its block newBlockEntity returns null and tile bind method is incomplete. Do not teach a camera-hologram survival route from those class names. Actual registered Planarium is a separate remaining device audit.

Optional teaching spine: craft/place Crystal -> create/name Scroll -> pedestal/Oculus selection -> exit camera -> inscribe/bind Eye -> cast harmless known effect at local target. Quest tasks can detect items; viewing, binding, successful dispatch and effect need manual observation or a separately implemented detector. Reward XP and modest parchment/build supplies; do not reward an advanced Eye as an item-possession proof of remote operation.

Unrun acceptance: direct view and remote view of loaded same-world Crystal; shift exit and camera switching; unloaded/removed destination; blank offhand override; identical coordinates across dimensions; two viewers/comparator count and disconnect/removal cleanup. For casting, compare Projectile/Touch/Self, target hit versus canceled event, no mana versus sufficient mana, and actual personal mana deltas across two debit calls. Test full inventory parchment creation (world drop rather than lost output), scroll rebind/reset, pedestal range edge and protected-target permission under actual pack policy. No compatibility, exploit permission or in-world PASS is claimed.
