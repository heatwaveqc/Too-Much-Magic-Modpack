## Setup, guide and payment order

Use the native Worn Notebook **Ritual Index → Performing Rituals**, Ritual Brazier and the matching named tablet entry. Native Documentation iterates RitualRegistry, generates each registered tablet's intro and exact-ID recipe pages; addon AEDocumentation need not explicitly repeat these. Craft tablet with JEI/Notebook, install into brazier, optionally feed accepted augment **before activation**, then interact with empty main hand. Native default augmentation consumes1item per accepted call; loose items within inflate1 are scanned every5ticks while not running. Power pauses ticks; use the native chassis report for replacement/refund/relay caveats. These are optional utility branches, not a mandatory linear tier ladder.

Initial context has needsSource=false; onStart only marks started. These six do not override that start. A positive declared Source cost **does not impose an upfront fee**. Persistent rituals apply their first batch and then setNeedsSource(true). On the next brazier tick a single pending request is paid from nearby Source through native helper range6; failure suspends ticking with20-counter backoff. Multiple targets set one boolean, not one bill per target. Empty scans usually request nothing. No augmentation or tablet refund is promised after running. Source units are neither personal spell mana nor fluid.

Periods are modulo **global gameTime**, not guaranteed intervals counted from activation. Inflated block AABBs are cubes/boxes rather than exact radial spheres; do not turn prose radius into a spherical entity filter. Attraction blacklist contains Player, `#c:bosses`, native follow_proj and `#ars_nouveau:familiar`. Attraction inside distance1 skips movement and the needsSource statement for that iteration; an all-near-center batch can avoid a new request.

RepelEffect applies each tick only while its MobEffectInstance is Sauce PosCarryMEI. It iterates carried origins; within actual Euclidean distance<15 of each, velocity=(old+normalized vector away)×0.5. Thus cube acquisition and spherical force differ. PosCarryMEI merges origin sets on update before the vanilla update result; overlapping rituals can leave multiple origins. Persistence/network reconstitution of this custom instance is untested; do not promise permanent exclusion, teleportation prevention or full boss immunity when using Bone's alternate predicate.

Zapping's chosen-target Player exclusion is **not a player-safe area**. Native LightningEntity queries all alive entities in its own bolt box(x/z±3,y−3..+9), calls lightning events/thunderHit and applies Shocked200ticks to first-hit living entities; nearby players/tamed creatures can be collateral. One bolt per clustered target can overlap. Ritual does not set amps/ampScalar/wetBonus; native damage multiplies by1 plus each worn/held stack exposing FE storage. No hitEntities guard around thunderHit itself; it guards Shocked refresh/list bookkeeping. Native tick does not call its private igniteBlocks helper, so this audit does not claim ritual-generated fire. Exact damage, cancellation interactions, deaths/drops and charging other mods require separate acceptance, not a safe automated farm promise.

Pollination does not create flowers/bees, begin their pollination goal or shorten hive residence. Supply outdoor bees and flowers, observe pollen/nectar cycle, then inspect actual hive output separately. Fast Squirrels buffs all matching nearby workers, including another player's; actual throughput remains AI/task/terrain-limited and unmeasured.
