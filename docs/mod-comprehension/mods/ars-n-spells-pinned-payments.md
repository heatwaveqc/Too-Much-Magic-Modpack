## Ars resolver path

`ArsCastPayments.quoteEvent` operates only on server player contexts. It uses CrossCastContext to choose reusable-book cross carrier versus native-only, captures one quote per SpellContext from nonnegative event.currentCost and current rules, and updates displayed cross cost from captured origin×multiplier. Ordinary native Ars with mana integration disabled returns without a managed plan. Later repeated quote events do not automatically replace an existing plan.

`MixinSpellResolverPreCast` intercepts enoughMana after getResolveCost and uses managed plan affordability (creative exempt, already-prepared true). At postEvent RETURN, canceled SpellCastEvent releases plan; otherwise prepare attempts ledger reservation and cancels event if that fails. prepare checks recovery/unreleased compensation first, skips absent/creative/already-prepared plan, checks every quoted leg, opens ledger attempt, reserves and refunds failed reservation. A successful reservation is held before effect dispatch rather than a second native mana debit.

`MixinSpellResolverMana` intercepts expendMana HEAD: commits optional category cooldown, then `ArsCastPayments.commit`; if commit succeeds it cancels native expendMana. Commit requires prepared plan unless creative/alreadycommitted, commits/completes ledger and marks committed. RETURN hooks on all three onCast variants call finish; uncommitted active attempts cancel/refund, committed ones retain payment. ServerTick.Post finishes still-reserved contexts, logout finishes that player's reservations, server stopping finishes reservations/clears plans. These handlers are cleanup evidence, not proof recovery across arbitrary process crash is complete.

Once native resolver reaches its payment/effect boundary, target success is separate. Do not promise mana refunds for missed projectile/no matching processing item or reclassify a cast advancement as effect proof. Exact native resolver payment-after-form behavior is covered by [parent casting](ars-nouveau-pinned-casting.md); this addon replaces debit for handled plans.

## Iron's normal and cross-carrier path

`IronsCastPayments.shouldCharge`: source consumesMana or SCROLL with config scroll_cost_modefull; exempt if Ars proxy ID, creative with native creative-mana-costoff, or existing native recast. CrossCastContext only selects cross carrier when type and spellID match. Precast LOWEST captures plan and initiates session; final `SpellOnCastEvent` can change cost, which is requoted against captured rules/native ceilings. Negative event mana cost rejects; unpaid exemption explicitly states zero event cost.

Pinned Iron's3.16.3 `AbstractSpell.castSpell` normally posts SpellOnCastEvent, conditionally computes max(current−eventcost,0) and writes mana, calls onCast, updates recasts/cooldown and sends client packet. This establishes actual callsites targeted by addon mixins; it is not a generic assumption about another Iron's release.

`MixinIronsCastPayment` wraps that invocation with an identity/pricing session; after posted event it prices/rejects before native effect. Non-mana sources requiring full-scroll payment reserve immediately. Mana-consuming sources leave an owed outcome until actual native setMana call; `IronsCastLifecycle.nativeWrite` reserves through NativePayment.hold and replaces that native write when successful, preventing a second debit. If another integration skips the native write entirely, startEffect explicitly **waives the owed payment** and logs native_write_skipped. Thus “every effect always pays addon quote” is stronger than this code supports; it respects upstream write-skipping paths.

At onCast entry, startEffect rechecks identity/pricing and accepted outcome, commits held payment/alternative leg and marks started. finishEffect marks actual method return and records cooldown eligibility. Outer wrapper catches payment refusal/runtime exception, aborts and exits; if effect never reached, notReached attempts pre-effect refund and releases optional alternative leg. abort refunds only while frame.startedfalse. An exception after effect entry does not refund committed payment; it ends/cancels native cast, resets casting state and stops item use. This boundary prevents a general “failed effect means refund” tutorial claim.

## Sessions, channel pulses and postcast changes

`IronsCastLifecycle.enter/boundaryFailure` reject reentrant/nonowner, changed player/spell/level/source/carrier, terminal session, changed pricing, repeated noncontinuous effect, or repeated continuous duration value. Session stores pricing generation and carrier identity; changing config/equipment/carrier during casting can matter separately from merely seeing enough mana at initiation.

Each continuous paid effect completes its own payment. afterEffect checks whether another identical quote is affordable; if not, marks exhausted. `MixinIronsCastTicker` wraps native MagicManager.lambda$tick$0 and checks after each of three native castSpell sites: aborted invocation cancels remaining caller path; exhausted channel invokes completion. Completion applies applicable native cooldown, consumes a SCROLL via native Scroll.attemptRemoveScrollAfterCast, calls onServerCastComplete(false) and stops the cast via the lifecycle path. The last paid pulse is not rolled back merely because there is no mana for another. `affordsAnotherPulse` returns true on adapter read exception, so final settlement remains responsible for refusing unusable payment rather than treating that preliminary check as proof.

The ticker defers native per-pulse affordability when addon owns the priced plan, avoiding a mismatched single-pool early check. Native `canBeCastedBy` is wrapped in CastValidationScope for server players rather than globally making validation succeed. Native cooldown/learning/source restrictions still need to be observed in the complete pipeline. Logout/clone/stop clear plans and lifecycle sessions.

## Optional alternative payment boundary

`AlternativePayment.reserve` supports explicitly selected resource adapters and failure policy, not an unconditional “all mana mods share a pool.” Rejects invalid amounts; zero is free reservation; cap4096open; checks compatibility/current resource, observes actual debit and tracks moved/reported/unknown state. Unusable/short adapter under **LEGACY_OPEN** can return reserved-short and allow unpaid/partial casts with warning; refusal policy denies instead. Error/unknown/overdebit paths attempt release and retain unresolved state. Release credits only known movement and tracks remaining/unknown; no guaranteed restitution if adapter refuses/clamps. Full adapter registration/installed-target mapping and current failure-policy default/caller path still need reconciliation, so no concrete third-party drain is claimed here.

## Walkthrough and acceptance implications

Player lesson: inspect active mode/JEI costs and both pools before a safe cast, observe one accepted effect and resource delta, then repeat with exact shortage. For channelled spells count pulses and final scroll/cooldown state. Keep native recast, creative and proxy exemptions distinct from survival free casting. No new survival currency/tier is added by this transaction implementation. Future rewarded quests should use actual cast criteria from [carrier audit](ars-n-spells-pinned-carriers.md), with output/effect observation explicitly separate.
