## First spell and all22 choices

Read Runic Tablet **Spellcraft → Mortar / Imbuer / Modifiers / Terra** and the named component page. Put the row's recipe items into Mortar plus a mixing base: Old Root permits0 modifiers, Verdant Sprig1, Infernal Bulb2, Dragon's Eye3. Add Glowstone Dust for potency, Redstone for efficiency, Gunpowder for size, within total capacity; use Pestle on Mortar. Mixing base is consumed in **Mortar**, not added to Imbuer. Component serializer need_mixin defaults true; supplements are filtered out of main recipe matching. Pestle crafting remainder is a fresh Pestle, not proof every use has no durability cost.

Take powder with SpellData, put wooden-rod-tag item and powder into Imbuer. Native server callback progresses past40 ticks, creates one staff, transfers effect/P/E/size and uses budget, consumes input and spawns result. Ordinary staff has native15+15×efficiency uses. Hold/release at least13 ticks; one use is removed before Terra affordability. Base maximum40; ordinary cost=table cost/(efficiency+1). No universal bridge to another mod's mana.

Notation: P=effective potency; S=effect-size argument3+2×powder size for release casts, while held castingAction receives raw size modifier. Spell target boxes usually center three blocks along caster look; ray-target spells have their own reach. Requested damage is not measured final HP loss. Many area components exclude caster via UUID comparison, but immunity/ally/PvP treatment is not uniform: disablePVP only appears in selected damage classes, not every movement/world effect.

## Crystal Staff, armor and advanced gear

**Crystal Staff:** obtain via named ritual, then use level1 Imbuer ritual with staff+Verdant Sprig on altar and1..4 Spell Powder incenses. It creates a fresh staff with first4 recorded powder effects; prior staff spell/state is not copied by that path. Sneak-use cycles1→2→3→4→1; ordinary hold/release casts selected slot. Native release uses selected potency+1 (another+1 with full Sylvan set), costs Terra as ordinary staff, and has no finite StaffUses decrement. **No natural-ground check or health-cost fallback appears in pinned CrystalStaffItem**, contrary to old guide/profile prose. Do not teach an unenforced terrain restriction or a health-payment route. Empty/unpopulated slots, list bounds and client cycling require acceptance.

**Living Tools:** exact level0 rituals upgrade wooden tools using Verdant Sprig/Gold Nugget/two Oak Bark incense. Living tools call shared randomlyRepair: if damaged,1/80 chance each inventory tick to reduce damage1. No repair-material support is established by these classes. This is random self-repair, not a fixed repair/second guarantee. Ordinary actual tool tiers/attributes come from registration and vanilla mining rules, not the word “living.”

**Sylvan armor:** named level1 rituals, full set provides potency+1 in both staff release methods. **Wildwood armor:** named level2 rituals, worn damaged pieces randomly repair through same1/80 helper; full exact set gets2% chance each eligible player tick to heal1 when below max. That handler changes health, **not Terra regeneration**, despite tooltip wording. Both sets remain separate optional specializations, not mandatory combined armor.

**Engraved Blade:** level2 recipe plus up to4 bark incenses, modifier map in ritual appendix. Native damage event adds Spikes1/level; Holy1.5/level against UNDEAD tag; Aquatic requests0.5/level drown damage; held blade Shadowstep can cancel incoming damage with12.5%/level chance. Whole-artifact field-reference scan finds Forceful only in component registration, ritual assignment and item tooltip, with no native event consumer. A knockback effect is not implemented by the inspected native references; do not promise it. No repair input in item class. Quest detection should inspect actual modifiers or explicitly use a possession proxy.

**Runic Focus / Charged Runic Focus:** recipe outputs are recorded in ritual appendix. RunicFocusItem itself adds only the IManaRelatedItem marker; no spellcasting/mana transfer operation is present there. Whole-artifact field-reference scan finds the two focus fields only in item registration, recipe datagen and ResearchManager. No native operation/charge-transfer consumer was found. They have recipes/guide entries but are not a demonstrated functional new casting tier or universal focus. An external adapter would be a separate integration.

**Dragon's Eye and supplies:** Dragon's Eye is also food: server tries up to32 random teleports within roughly±16 X/Z and Y−8..+23 (clamped), stops riding, plays teleport sound and applies20-tick item cooldown for players. Growth Powder recipe gives4 from wheat-seed tag+Short Grass+Redstone-dust tag+Pestle; its helper only consumes powder when returned success, and Water→Lily Pad branch returns false despite setting block. Healing foods/poultice and bark/material uses remain ordinary recipe/guide references, not a new altar tier.

## All three rare flower mutations

Craft Mutating Powder from4 Growth Powder, one Nether Star tag item, Nether Wart crop tag and reusable-crafting Pestle. Use at ray-selected plant within4 with dropped offerings intersecting the surrounding5×5×5 volume. **Powder is consumed in survival even if no recipe succeeds**. On match, target plant replaced and all scanned ItemEntities discarded, not just one unit of nominal ingredients. No returned Lava Bucket is provided in this handler. Keep unrelated/large item stacks away.

**Matcher discrepancy:** MutagenRecipe copies the list of ItemEntity stacks and removes a match for each expected ingredient, but does not fail when a required ingredient is missing; succeeds if no scanned stacks remain. A nonempty subset of nominal offerings can therefore pass if all supplied entries are removed. It ignores stack unit counts for matching, then the item handler discards whole entities. Use nominal safe instructions; record actual mismatch as a source bug, not a balanced free-mutation feature. Environmental predicates still apply.
