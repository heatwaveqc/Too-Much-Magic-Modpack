## First functioning altar and Forge setup

1. Obtain/open the Black Book using [the parent onboarding](goety.md#guidebook-onboarding--required-before-the-players-first-complex-step). Read **Rituals → Performing Rituals**, bundled `assets/goety/patchouli_books/black_book/en_us/entries/rituals/dark_altar.json`.
2. Craft a Cursed Cage, Dark Altar and enough Pedestals for the chosen JEI ritual. Place the Altar directly above the Cage and charge the Cage through the parent Totem/Soul Energy path. The alternate altar/pedestal stone variants are options, not separate mandatory progression tiers.
3. Sneak-use the Altar with an empty hand to display its range. The code's `MainConfig.ritualRange` default is **8**. Ordinary structure checks count qualifying placed blocks in the inclusive cube from −8 through +8 on each axis around the altar (17³ positions at that default), not a spherical eight-block distance. Read the actual config if changed. Pedestal, conversion and sacrifice detection also refer to the configurable ritual range; do not substitute the Fabricator's four-block sensor range.
4. For **Forge Ritual**, place one Lava Cauldron, two Furnaces and/or Blast Furnaces, and one Anvil inside that range. Counts are minimums, not a fixed diagram. The Java predicate accepts LavaCauldronBlock, FurnaceBlock/BlastFurnaceBlock and a block description ID containing `anvil`; vanilla examples are a safe teaching choice. A lava bucket on a pedestal is not the required placed Lava Cauldron. See **Rituals → Forge Ritual**, `entries/rituals/forge_ritual.json`.
5. Put the recipe's pedestal ingredients in place **before** adding its activation item to the altar. Supply the full nominal budget plus any separately documented costs; see the parent timing correction. Forge setup blocks and consumable pedestal ingredients are different roles. For a Fabricator, the ritual consumes a pedestal Anvil as an ingredient in addition to requiring an Anvil block in the surrounding Forge setup.
6. Keep the structure and required environment valid until completion. Collect the output or confirm the actual summoned/converted entity. An altar item does not prove any operation. Failure can return activation while retaining previously consumed pedestal materials and Soul Energy.

Do not advertise Grave Soil as a one-time permanent build; recheck the count after successful rites. This is code probability, not measured consumption. Other callbacks still need individual coverage.

## Research is a personal unlock, not scroll possession

`ResearchList` registers named research objects. `SEHelper.hasResearch/addResearch` reads and updates the player's Soul Energy capability and sends an update packet. `ResearchScroll.use` grants previously unknown research and consumes the scroll only after a successful add. For an ordinary scroll that the player already knows, the method emits `CONSUME_ITEM` and the already-known message without shrinking the stack. Therefore an advancement may record use even when no new research was granted. `ExtraScroll` adds a prerequisite; Terminus is registered with **Warred** as that prerequisite.

`DarkAltarBlockEntity.activate` (the method containing the start checks) checks valid recipe/structure, conversion candidate and summon cap, then requires recognized recipe research from the casting player. The Forbidden branch has a separate `lichScrollRequirement` config default true; disabling it bypasses that branch's research check. Do not generalize it to other scrolls. Unknown research IDs are not automatically proven valid gates; the code only invokes the named research test if `ResearchList.getResearch` resolves the string.

### Ender Keeper reward boundary

`common/entities/boss/EnderKeeper.class#dropCustomDeathLoot` checks `doMobLoot`. With no resolved Void Shrine it drops a glowing, extended-life Shrouded Blueprint item. With a shrine it looks for a block item handler at its bound position and inserts into slot 0 **only if that slot is empty**. A caught NullPointerException falls back to a drop. The ordinary shrine branch with absent handler or occupied slot does not show that fallback. Thus a full/unavailable shrine handler can be a reward-loss boundary; do not promise a ground drop on every kill. Source proves branch ordering, not that ordinary gameplay creates that exact blocked state.

## Disposable-world checks — none run

- Forge: valid minimum inside range succeeds; remove one furnace, empty the lava cauldron, move an Anvil to radius+1, or provide only an Anvil pedestal item. Record recipe start versus post-start interruption losses separately.
- Deep: waterlogged altar plus deep-ocean sea-level condition succeeds without alternative blocks; repeat dry and outside the biome; alternative blocks may replace biome/height but must not replace waterlogging.
- Storm: thunder plus exposed sky plus Sky condition and Storm counts; compare rain, roof and low altitude without Sky blocks. Do not infer weather from visual rain alone.
- Necroturgy: valid nighttime/skylit setup; compare daylight and a no-skylight dimension. Record Grave Soil before/after repeated successful rituals, repair count or use Sculk, and verify rewards do not fund an unintended loop.
- Research: learned versus unlearned player with identical inventories; consume new versus already-known ordinary scroll; use gifted Terminus without Warred. Check stack count, capability, advancement credit and altar start independently.
- Ender Keeper: `doMobLoot` true/false, no shrine, empty shrine slot, occupied slot and missing handler; record blueprint location/count and preservation through chunk reload before authoring any mandatory repeat-kill instruction.
