Ars Unification imports eligible physical processing recipes into magic. Farmer's Delight cutting becomes **Cut + Sensitive** on dropped items; Occultism crushing becomes native **Crush** recipes, most clearly taught with Sensitive on dropped items. It is useful for food preparation and compatible mineral processing without the corresponding physical workbench/spirit operation. Recipe conflicts, effective tags, disabled patterns and configured tiers determine actual availability; the supported upstream machine list is not a list of installed pack systems.

## Player walkthrough and guide access

1. Follow the parent's [guide/glyph acquisition](ars-nouveau-pinned-guide-glyphs.md) and [casting/book tiers](ars-nouveau-pinned-casting.md). Craft Worn Notebook from1Book +1lapis-gem-tag item and right-click it. Use **Getting Started**, then **Glyph Index → Tier One → Cut/Sensitive**; **Tier Two → Crush** after the Apprentice book upgrade. This is native Java documentation, not a missing Patchouli book. For nontrivial ingredient processing, the parent's [crafting companion](ars-nouveau-pinned-crafting.md) explains Imbuement Chamber/Apparatus steps and JEI references.
2. Make/learn Cut and Sensitive through Scribe's Table: select each glyph, supply the exact unit ingredients below and XP **points**, wait120ticks after the ingredients are supplied, collect its glyph item and right-click to learn it. Save `Touch → Cut → Sensitive` in the spellbook. Touch is a configurable default starter; check actual known glyphs rather than adding a new recipe requirement.
3. In JEI find **Cut Glyph** (the addon's `ars_unification:cut` recipe type); its catalyst is Cut with a Sensitive instruction tooltip. Inspect pumpkin or cabbage uses. Drop1pumpkin or1cabbage in a clear area, aim at the ground beside it and cast; expect4pumpkin slices or2cabbage leaves from the default recipe data. Use the items as food-preparation inputs. No physical knife, tool wear, Cutting Board, Source Jar or spirit is demanded by this adapter route.
4. For the separate crushing option, upgrade to an Apprentice book through the parent route and learn Crush. Save `Touch → Crush → Sensitive`. In native Ars JEI Crush recipes find an actual eligible imported recipe; use dropped ingredients whose tags resolve. The raw-iron example is a data-backed candidate, not a promise every pack tag/recipe survives priority filtering. Collect output and compare its input/output amounts against JEI and effective server tier/multiplier.
5. Optional: add AoE/Pierce only after testing a small batch; separate incompatible inputs and watch item counts and mana. Batch casting is the addon endpoint, not another hidden tier. The addon does not provide a new automated collector: player pickup or an already-researched compatible worker is a separate system, with its own capacity/ownership/failure tests.
6. If nothing transforms, check Sensitive, nearby dropped-item position, mana, correct held book tier/known glyphs, JEI availability, tags, native recipe collision, exclusion regex and enabled adapter priority. A cast without an eligible item can still cost mana. Physical-machine times/tool conditions are not necessarily reproduced by imported recipes.

## Import ordering, casting and two-sided recipe receipt — 2026-11-18

Direct binary paths: `ArsUnification.processRecipes`, `Processor.processRecipes/getSortedRecipes/makeRecipe`, `RecipeWrapper`, `EffectCutMixin.wrapResolve`, `ItemUtil.processItems`, `GenericRecipeCache`, `CutRecipe.rollOutputs`; native Ars `EffectCrush` from the hash-verified 5.13.5 artifact.

**Import is server-side recipe conversion.** The addon registers a SERVER config, not a COMMON config. After config is loaded, processors sort by descending priority; `-1` or absent target mod skips that processor. Within each processor, original IDs sort lexicographically. Existing target-type inputs are collected first, and each successful import claims its input item IDs, so prior native/custom target recipes and earlier imports take precedence. Farmer's Delight default priority is60; Occultism115. The priorities apply within their processing types rather than making Cut displace Crush.

`Processor` rejects excluded IDs, null/empty ingredients, vanilla ingredients with multiple values, empty item alternatives, input stacks whose count is not1, and already-claimed item IDs. It can reduce a tag to its remaining item alternatives. Custom/other ingredients are flattened to their exposed item stacks; this does not preserve a promise of arbitrary custom component/predicate semantics. Import retains the original machine recipe and adds `ars_unification:cut/<original namespace>/<original path>` or `ars_unification:crush/...`; it does **not** retain the original ID unchanged. Imported recipes enter the recipe manager on startup/datapack synchronization; recipe counts in a JAR are not the count of live eligible imports.

**Cut item route.** Learn native Cut and Sensitive through the Ars guide/Scribe route, save `Touch → Cut → Sensitive`, drop eligible inputs near the aimed block and cast. On a server, Sensitive intercepts Cut before ordinary resolution: search box is the hit block's unit box inflated by `1 + AoE multiplier`; per-cast input-item limit is integer `4 + 4×AoE multiplier + 4×Pierce count`. The helper finds matching recipes, rolls outputs (once and scaled for deterministic outputs; independently per input otherwise), then shrinks input stacks. Invalid inputs are skipped. Output stacks become dropped item entities; a fully used input entity can be reused for the first output with pickup delay0 and refreshed lifetime. Failed world insertion is not refunded here. Normal Cut is called when this interception condition does not apply. A successful normal cast can still spend personal mana when nothing eligible is nearby; the helper does not add a Source bill or a recipe-specific mana bill. Ars Technica doubling branches exist in the binary but are conditional optional integration, not a native unconditional multiplier.

**Crush item route.** Use native `Touch → Crush → Sensitive` on dropped items. Native `EffectCrush` uses the same `4 + 4×AoE + 4×Pierce` limit and hit-block inflated box, consumes one item per matching roll and spawns output entities. Imported Occultism recipes are ordinary Ars Crush recipes; no live spirit or native crushing-time wait is copied into the wrapper. Without Sensitive, Crush retains entity damage/block transformation behavior; use the item route for an unambiguous tutorial. Personal casting mana remains the parent spell engine's cost; recipe conversion itself does not debit mana, durability or Source.

**Recipe cache boundary.** Cut cache starts at8 entries, caches both hits and same-item/same-component misses, and clears on all-player datapack synchronization. A cached miss can matter while debugging reload state; it is not evidence the source recipe never existed. The import excludes original machine IDs using case-insensitive anchored regex matching, compiled on config loading. Effective world settings must be checked separately; no checked-in Unification config was found under `config`/`defaultconfigs` in this research checkout.

## Recipient defaults and probability boundary

`Occultism1.227.0/CrushingRecipe.CODEC` defaults omitted min/max tiers to **-1** (unbounded), crushing time to200ticks and ignore-multiplier tofalse. `OccultismServerConfig.SpiritJobSettings.TierSpiritSettings` defines output multipliers **1.0/1.5/2.0/3.0** for Foliot/Djinni/Afrit/Marid. Combined with adapter default tier1, a qualifying raw-iron recipe gives2dust-tag units, while ingot gives1 because ignore-multiplier istrue. Hypothetical tier2 would give3raw-input dust units, tier3→4, tier4→6, provided server settings and tags/priority permit. These are default formulas, not permission to change tier/config or observed runtime output. Bound recipe data excludes `ice_dust`, `packed_ice_dust`, `blue_ice_dust` below2 and `echo_dust` below4. Import does not retain crushing time, so these are spell conversions, not time-faithful Crusher Spirit simulations.

Farmer's Delight `CuttingBoardRecipe.getIngredients` returns only its input; `matches` separately tests input **and tool**. `ChanceResult.CODEC` defaults omitted chance to1.0, confirming the two tutorial outputs are deterministic. Crucially, its physical `rollOutput` tests chance **per output unit** and incorporates knife Fortune bonus. Addon's `CutRecipe.rollOutputs` instead rolls once **per output entry** with `random.nextDouble() <= chance`, copies that entire output stack on success, and does not use physical knife Fortune here. The processor copied quantities/chances, not the physical random distribution. For a2unit50%output, the ordinary no-Fortune board can yield0/1/2 whereas imported magic yields0or2. This distinction matters for statistical testing; deterministic pumpkin/cabbage remain simple teaching examples.

`JeiArsUnificationPlugin` registers **Cut Glyph**, its recipes from the live client recipe manager and a Cut catalyst augmented with Sensitive tooltip; `CutRecipeCategory` shows input, each output, percent chance and range. Flatten category/catalyst requires Not Enough Glyphs. Crush wrappers use Ars native Crush recipe type rather than a new addon-only Crush category. JEI render/reload behavior still needs client acceptance; the displayed animated arrow is not processing time or proof of a successful cast.
