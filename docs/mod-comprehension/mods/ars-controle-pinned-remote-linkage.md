## Remote controls and order

`RemoteItem` implements native IRadialProvider. Native radial key opens Single/Multiple selection; **sneak + radial key** opens LockedFirst/LockedLast. Use configured keybind in Controls rather than invent a hardcoded key. PacketSetRemoteSelectionMode/LockMode operate on sender's current **mainhand Remote** and write chosen mode; clearing handler similarly empties target/firstcorner while preserving modes. Exact user-facing clear-button/key path remains to be reconciled in final client/control audit; packet existence alone is not a usable reset gesture.

Block use is server/mainhand only, requires player and posts ANEventBus BlockEvent.BreakEvent on **clicked block** before recording/dispatch; canceled event fails. Don't confuse that event hook with a remote target ownership check. If stored target dimension doesn't resolve, report invaliddimension; stored target need not be IWandable when selected, because a later clicked endpoint may be the wandable one.

Dispatch from **block click** when stored block's tile is IWandable: lockedFirst→stored.onFirstConnection(clickedGlobalPos,clickedFace); unlocked→stored.onLastConnection(clickedGlobalPos,clickedFace). Otherwise if clickedtileIWandable: lockedFirst→clicked.onLastConnection(storedGlobalPos),unlocked→clicked.onFirstConnection(storedGlobalPos). This preserves conceptual first/last pairing while selecting which side implements it. Return CONSUME means Remote handled request, not that endpoint returned successful operation; endpoint return values aren't used here to certify transfer.

Entity-click branch reverses dispatch names relative to that block-click branch: when storedblockIWandable, lockedFirst→stored.onLastConnection(entity),unlocked→onFirstConnection; if clickedentityIWandable, lockedFirst→clicked.onFirstConnection(storedBlock),unlocked→onLastConnection. Storedentity branch likewise dispatches to whichever side is IWandable; a non-IWandable storedlivingentity can be supplied to clicked block/entity handler. Do not teach that lock-mode label guarantees one identical method name across every endpoint kind. Per-endpoint support and actual observed state are required.

Multiple mode records first clicked corner in currentdimension, then iterates inclusive BlockPos.betweenClosed to secondcorner and clears firstcorner. Dimension mismatch starts a new firstcorner. Depending on stored endpoint, it dispatches each position or each IWandable tile in selection; one branch skips empty states. No volume cap/fuel/mana debit is visible in these loops. Large-volume selection could therefore have substantial work; start with two nearby blocks, don't deliberately stress a live world during research. Invalid endpoints/handler refusal can coexist with a consumed interaction status.

Remote stores no peruse mana/Source/durability debit in these methods. Endpoint behavior may still incur its own costs or enforce restrictions. Cached entity lookup searches currently available entities across serverlevels, accepts live cached/loadedentityUUID, weakvaluecacheexpires10minutes afteraccess; no persistent offlineentity loading guarantee. Selected Remote sends highlights each5gameticks,10ticklifetime, using dimensional highlighter if supplied else native IWandable; visual outline is not proof target loaded/owned/working.

## Linkage binding, state and capability contracts

`ScryersLinkageTile.setBlock` invalidates all query caches **before** checking locallevel and blacklist. Valid target stores GlobalPos attachment and notifies changed, invalidates capabilities and updates redstone/neighbors/shapes. Refused target does not write a new attachment but cache invalidation already occurred; don't promise all rejected actions preserve every transient state. removeBlock clears attachment/cache and notifies. Binding methods resolve dimension and reject invalid/blacklisted; direct method has no distance or owner UUID gate. Crossdimension target storage is supported by this code, correcting earlier README-only broad crossdimension rejection claim.

Exact data tag `ars_controle:scryers_linkage_blacklist` contains native `ars_nouveau:storage_lectern` and Linkage itself; effective tags can add more. Startup capability class blacklist defaults native LecternInvWrapper and optional AE2 IInWorldGridNodeHost, resolved at configloading. AE2 is not permission to add an excluded mod. Block-tag gate and capability-class gate are different checks; both matter.

`ArsControle.onRegisterCapabilities` iterates BlockCapability.getAll and registers forwarding for Linkage except capabilities whose declaredtype matches a blacklistedclass. Provider calls tile.getCapability, then rejects returned implementation whose class matches blacklist. StackOverflowError catches recursivecapabilityquery, warns and removes target; ClassCastException during registration logs. This establishes a generic capability proxy, **not** separate newly implemented handlers for every item/fluid/energy API nor guaranteed all late-registered capabilities are exposed.

Tile query: resolve target dimension/position, key cache by **capability+originalcontext**, create native BlockCapabilityCache against targetserverlevel/block and pass context unchanged, return its handler. One-minute expireAfterAccess cache; bindingclear invalidates all. Sided queries retain caller context, so side restrictions can affect results. Missing target information yieldsnull; ExecutionException becomesRuntimeException. No capability-specific item debit, fluid conversion, FE generation or ownership layer is added here; target/caller contracts govern actual behavior. No explicit chunkloader ticket in these inspected methods, so crossdimension lookup isn't guarantee of operation in unloaded chunks.

## Redstone/comparator forwarding and change detection

`ScryersLinkageBlock` delegates weak/direct signal to target block's getSignal/getDirectSignal with same side. Comparator value calls target getAnalogOutputSignal; canConnectRedstone delegates target block. hasAnalogOutputSignal is generallytrue but contextual check queries target and supports ContextualAnalogSignalling. This is **reading/forwarding target output**, not teaching a wire to transmit arbitrary local input into target without an evidenced inverse path.

Ticker keeps weakreference to local tile and target blockentity identity. No target→invalidate on transition; missinginfo resets cachedidentity; changedtargetidentity→invalidate capabilities. With target, it updates neighboring/redstone output eachtick. Same targettile state changes still depend on native capability invalidation/state APIs and neighbor polling; no throughput measurement follows. Multiple linked consumers can share one target handler; no snapshot inventory/fullinsert guarantee.

Empty-hand interaction reports target GlobalPos/highlights; it posts BreakEvent on local Linkage before proceeding. Claims/permissions at remote endpoint, infinite recursion through other capability proxies and effective blacklist changes require tests.
