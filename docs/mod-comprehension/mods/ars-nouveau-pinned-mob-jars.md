## Direct use and shared behavior infrastructure

Empty Jar can accept Spawn Egg (creates type instance, survival egg-1) or arbitrary nonempty held stack (except MobJarItem and ANFakePlayer path) as copied ItemEntity then sets held stack count0. These are distinct from ritual canJar checks; do not assume capture whitelist/blacklist applies identically. Item interaction blacklist checks held item before these branches. Whole stack insertion can be destructive if its reconstructed state doesn't persist; ordinary items are not automatic entity drops.

Occupied Jar may forward interactions to cached entity or registered JarBehavior. Default JarBehavior blocks INTERACT_JAR_BLACKLIST then invokes held-item interactLivingEntity and/or Mob.interact with sync. Known behavior table **replaces** default fallback selection; subclass default methods still inherited. Registry supports multiple behaviors per exact EntityType; native24registrations below, not arbitrary subclass-wide matching. PlayerRideable/ContainerEntity handling and JarEvents mount cancellation prevent ordinary “ride inside jar” inference. Secondary-use container-vehicle path calls its normal inventory interaction.

Shared insertOrCreateItem inserts through InventoryManager at tile and spawns remainder above Jar with default pickup delay. This retains output rather than silently claiming infinite internal buffering. Comparator takes max behavior analog output, clamp15; default occupied15/empty0. Ordinary redstone output separately uses behavior getSignalPower. Rising edge dispatches onRedstonePower **before POWERED state flips**; this matters to methods checking !isPowered. Held high doesn't repeatedly generate edge actions; some tick actions use POWERED as pause, others enable while powered.

Note Block directly above Jar: registered event substitutes cached mob ambient sound and cancels note, or plays lightning thunder/impact for lightning entity. This is audio, not a resource generation/capture detector. Drygmy consults Jar entities separately as described in its companion; Jar capture doesn't bypass Drygmy blacklist/boss eligibility.
