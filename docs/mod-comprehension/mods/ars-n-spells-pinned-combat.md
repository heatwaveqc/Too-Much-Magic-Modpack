## School selection and passive advancement

`SpellAnalysis.analyzeRecipe` selects first cast method, first effect (or first filter as fallback classifier), and all effects. Primary school derives from classifier; all-school set comes from every effect's SchoolResolver results. Category derives from classifier registry path, not necessarily the last glyph or damage type that hits a target. Generic/unknown school is not automatically a real elemental progression entry. Changing effect order can change credit and primary scaling. Effective school mappings are separately loaded/configurable, not a promise every addon glyph maps to its name's apparent element.

`ProgressionHandler` listens to native Ars SpellCastEvent; `IronsProgressionHandler` to Iron's SpellOnCastEvent and excludes addon Ars proxy spell IDs. Both require enable_progression_system and enable_cross_mod_progression; fresh defaults true. Ars generic is skipped. Increment uses per-school cast count saturating at Integer.MAX_VALUE; `ProgressionData.getBonusForSchool=min(cap,casts×perCast)`, defaults .25 and .001, reaching nominal25% after250event counts. `ProgressionAttributes` replaces its transient ADD_VALUE modifier on resolved Iron's school power attribute and removes older modifier ID; missing Iron's/attribute prevents application. This is school-attribute growth, not XP orbs, item tiers or a globally stacking bonus for every spell.

These handlers act at **cast events**, not confirmed target damage/kill. Iron's SpellOnCastEvent occurs before the final addon payment/effect boundary described in payment companion; later payment refusal can occur after the progression listener saw it. Do not use these counts as proof every attempt was paid/effective or invent a kill requirement. Serialized attachment copies on death; login re-applies school bonuses. Whether event ordering/cancellation by another mod changes counts needs acceptance.

## Affinity and decay

`AffinityHandler`/`IronsAffinityHandler` similarly use those cast events, skip generic Ars/proxy Iron's, add1to selected school's AffinityData and sync that school. enable_affinity_system defaulttrue. Affinity levels clamp0..100; `AffinityBonuses.getAttributeMultiplier=1+min(.5,level×.005)`, maximum1.5at100. Actual consumer found in `SpellScalingUtil` for Ars outgoing damage; this scan does not establish a universal separate Iron's affinity multiplier. Per-school progression on Iron's attributes is a different channel. Don't confuse addon affinity with another installed Ars Affinity perk tree.

Affinity attachment schema2serializes levels, fractional decay remainders and unresolved legacy keys, copies on death; legacy aliases normalize/merge by maximum and unknowns retain separately. Optional decay defaults **off**. Enabled `AffinityDecayHandler` runs only serverplayer tickcount%interval==0, default1200ticks, rate.01per24000ticks: accumulates `currentLevel × rate × interval/24000`, subtracts whole accrued units, floors0and syncs changes. It visits all nonzero stored schools, not a timestamp check that explicitly exempts the school most recently cast. No offline timer is advanced by this PlayerTick handler. Returning to a matching school can add levels, but “only unused schools decay” is not demonstrated by this implementation.

## Two damage directions and actual caps

`ArsDamageBridge` handles Ars SpellDamageEvent.Pre at LOW only when cross combat and Iron's-power-for-Ars flags enabled, casterServerPlayer, damagepositive and valid nonempty context spell. It multiplies event.damage by SpellScalingUtil breakdown. Native Iron's3.16.3 globals/school attributes are read from player; multi-school policy defaultsprimary, optionallymaxoraverage, not sum. Missing matching school attribute contributes neutral1.

Exact combined multiplier is `clamp((globalPower + schoolPower −1) × affinity × resonance, 0, spellPowerCap)`, defaultcap3. Affinity uses **primary** school even when school power is max/average. Resonance requires its master/Ars direction enabled. This cap constrains this derived multiplier, not all possible damage events/modifiers or total pack damage. No immunity bypass or PvP/claim compatibility is established.

`IronsDamageBridge` listens to Iron's SpellDamageEvent, requires both cross-combat/Ars-damage-for-Iron's flags and ServerPlayer source, skips Ars proxy IDs, then **adds** current Ars SPELL_DAMAGE_BONUS to native event amount. It doesn't apply the Ars multiplier formula or cap3in this method. Zero bonus leaves native amount. Native mitigation and other event handlers remain separate; positive/negative modifiers and source attribution must be tested. Mana unification disabled does not by itself disable these independently gated combat hooks.

## Resonance and fullness lifecycle

`ResonanceManager.computeResonance` runs via server PlayerTick.Post and requires mastertrue, mana integrationenabled and Iron'spresent; otherwise clears. Separate mode examines **native Ars** mana, others authoritative bridge. `ResonanceState.update` refuses nonfinite/invalidmax, clamps fraction=current/max0..1, uses threshold.95default. Above threshold returns `min(max(1,cap), 1 + fraction × max(0,strength) × .2)` and renews expiry atcurrenttick+duration. Defaults strength1, cap5, duration100ticks: fullmana gives1.2, threshold.95gives1.19. Belowthreshold retains previous value strictly whiletick<expiry, else neutral1. No steady upkeep payment here; spending mana can lower fullness and later remove bonus. Tick sampling/commentary is not a guarantee of wall-clock five seconds under lag.

Ars scaling consumes this resonance inside its capped formula. Iron's `MixinIronsSpellPowerResonance` multiplies native AbstractSpell.getSpellPower return when directional Iron's toggle permits; optional require0injection is not proof it applied in a live pack. Client uses synchronized cache; invalid received value ignored, finite clamps0..100. Login computes/syncs, logout clears, serverstopclearall, cleanupofflineevery1200serverticks. Defaultmastertrue doesn't imply current server settings or displayed effect accepted.

## Optional category cooldown versus bound-Ars native cooldown

UnifiedCooldownManager requires both enable_cooldown_system and enable_unified_cooldowns. Fresh master and cross-mod-cooldown flags arefalse, so category gates are an optional server rule, not an unconditional addon survival delay. Categories OFFENSIVE/DEFENSIVE/MOVEMENT/UTILITY derive from registry-path substring classification for Ars; e.g. harm/crush→offensive, heal/shield/regen/summon→defensive, blink/teleport/launch→movement, fallbackutility. Iron's categorizer uses school. Do not assume every spell's actual gameplay purpose matches heuristic label.

Ars precast handler cancels when category is active; native expendMana interception commits category endpoint using whether plan is cross-cast. Iron's precast gate excludes Ars proxies and requires cross-mod flag; after recorded successful effect/native cooldown addition, its Post handler commits category only for respecting sources/nonproxy spells. Failed delegated proxy cooldown is canceled in Pre. Manager stores **end tick** in CooldownData despite getLastCast naming; active whennow<end, remaining=max(0,end−now). Duration=(long)(baseDuration×crossMultiplier)forcross, baseotherwise; defaults100ticks and.5but gatedoff. Serialized cooldown attachment lacks copyOnDeath unlike affinity/progression. Client receives category endtick. Modded time/dimension/death/reload behavior needs tests.

Separate **native bound-Ars wheel proxy** cooldown: ArsCrossProxySpell.getSpellCooldown reads config on each cast; fresh default40ticks, permitted0..12000;0orunloadedconfig→off. This applies to Ars proxies in Iron's wheel, not ordinary Ars, ordinary Iron's or generic Iron's-carrier casts. Shared proxy slot IDs can share cooldown across books; native Iron's cooldown reduction/persistence remains its pipeline. AnsConfig schema migration: before3, nonfresh file value40resolves0to retain old behavior, explicit other boundedvaluepreserved; fresh/current schema preserves boundedvalue. Preset UI cycles0,10,20,40,60,100,200,400then0; these aren't the only allowed numeric values. Config migration isn't proof a particular existing world uses40.

## Teaching, rewards and unrun acceptance

After Loom/bind/cast, optional specialization lesson should show same primary school in a safe known spell, cast it, inspect progression/affinity and compare matching versus different school equipment; choose a useful spell rather than require repetitive250casts. Optional fullness lesson compares atmax/belowthreshold and waits beyond expiry; optional server category rules require observing actualenabledsettings. Use modestXP/common spell supplies, not free school ranks or unique-gate items. Current four pilot nodes don't teach all these choices; acquisition/cast acceptance criteria remain in carrier companion.

Not run: mixed-effect order/primaryvsmaxvsaverage; base/global/school/additive Ars bonus and caps; event seen then paymentrefused; affinity0/100andfractionaldecay including activelycastschool; death/loginmigration; full/.95/belowthreshold/expiry/poolmode; categorydisabled/enabled/zero/truncatedduration; sameproxyslotacrossbooks, failedproxy/no cooldown and oldconfigmigration. These are source-backed cases, not server/client acceptance or balance approval.
