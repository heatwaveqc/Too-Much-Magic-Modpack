## Shared operation and timing

Obtain/open Dictionary of Spirits as main profile instructs. Use the named ritual under binding/summoning/familiar chapters and its Modonomicon pentacle construction preview; JEI recipe ID below is the exact reference. Build chalk/candle pattern around Golden Sacrificial Bowl, central activation item and additional ingredients in nearby Sacrificial Bowls (native scan range8). Arbitrary decorated circles do not pass pentacle.validate.

Ritual checks activation, remaining ingredients and pentacle; start checks optional condition. Bowl waits for required sacrifice/item-use events before advancing. Entity-type tags and RightClickItem stack checks are **event gates**, not automatically consumed extra stacks or outputs. Event distance/attribution hooks remain acceptance work. Ordinary tier1 advances duration counter every `int(20×ritualDurationMultiplier)` game ticks; tier2 every `int(5×multiplier)` with its very-low-multiplier fast path; other tiers set counter to full duration. Omitted JSON duration defaults30 via exact settings codec. Thus table duration is a counter/nominal seconds for tier1 at multiplier1, not game ticks; waiting/global settings change real time.

Ingredients are extracted gradually at duration/(ingredients+1). Ordinary interruption drops activation and consumed ingredients; it does not undo a sacrificed death/external use. NBT records/restores current recipe ID, caster, consumed ingredients, time and event flags. Reload/offline behavior remains untested.

| summon_spirit_with_job /26 | Base tame=true, initializes configured SpiritJob and lifetime on SpiritEntity; individual job behavior separate from acquisition. |
| summon_wild /15 | Loops summon_number, selects per iteration, random nearby position/generated name, no tame ownership. |
| summon_with_chance_of_chicken_tamed /1 | Registry constructs handler with tame=false despite name; configured entity1/3, Chicken2/3. |
| resurrect_familiar /2 | Consume shard before ENTITY_DATA parse; restore entity payload, clear old position, spawn at bowl, set Familiar/DemonicPartner owner to caster after add. Invalid/rejected result has no refund. |

Craft outputs prefer downward-facing empty Sacrificial Bowl1,2 or3 blocks above center, then dropped ItemEntity. Summon/resurrection Automation Flame uses realDrop=false: overhead-bowl delivery only, no loose flame fallback. Spawn booleans are not rollback gates; advancement can precede final add. Output possession and actual entity state are more reliable acceptance observations than a ritual trigger alone.
