## Native mechanics, relevant risks

1. **Natural spawning:** `[spawn]` has `minCount=1`, `maxCount=4`, `spawn_weight=8`, `spawnType=MONSTER`, `max_nearby=6`, `nearby_radius=48`, and empty `spawn_dimension_blacklist`. The default spawn-biome tag includes **`#minecraft:is_nether`** as well as forests, taiga and jungle. The spawn dimension blacklist is completely separate from teleport destinations and applies only to natural/chunk-generation spawn checks.
2. **Snow Angels:** `[snow_angels].snow_angels=true` controls a snowy-worldgen feature and requires a new-chunk test; do not conflate it with the regular mob spawn cap.
3. **Threat:** source attributes are 20 health, 8 attack damage, 2 armor, 0.8 movement speed and full knockback resistance; the AI halts when observed. No native attack-damage/health scalar was found in the reviewed configuration. Actual difficulty depends on modded stats, player class and the encounter environment.
4. **Damage:** default `[damage].hurt_type=PICKAXE_AND_GENERATOR` rejects spells, most weapons and empty-hand Monk attacks. The implementation checks the attacking player's **main-hand item**, including for other player-caused damage sources, rather than granting generic spell/unarmed damage. `ANYTHING` is the native compatibility option, though it also allows swords/arrows/etc. A tag-only workaround for magic/unarmed damage is insufficient: the native `attack/weeping_angels` tag checks a held item.
5. **Theft:** default `[behaviour].angel_theft=true` allows the Angel to take an **entire matching stack** from player main inventory; the default `stealable_items` tag contains clock, torch, compass, recovery compass and `#minecraft:pickaxes`. The Angel carries the stolen stack with guaranteed equipment drop and becomes persistent while holding it. This can strand a player without the intended counterweapon; modded tag additions and high-value pickaxes are potential balance hazards. **Owner locked permanent `angel_theft=false`; do not re-enable or add alternative theft.**
6. **Block behavior:** default `[behaviour].block_breaking=true`, together with `mobGriefing=true`, enables scanning for block reactions roughly every 400 ticks while observed, up to 25 horizontal and 3 vertical blocks away. Depending on block type, it can destroy emitting blocks, toggle lights/levers or extinguish candles. This affects redstone, magical fixtures and player-built structures. `block_breaking=false` disables **all** these interactions, not just physical destruction. The native `weeping_angels:no_breaking` block tag offers fine-grained exemption when restoring interactions later.

## Owner follow-up: physical-only vulnerability and structure encounters — 2026-11-20

**LOCKED:** set `[behaviour].angel_theft=false` permanently, with no later staged reintroduction. Applied in the PR candidate common TOML, still pending integration/pin verification.

**Damage goal (specific source implementation pending):** **unarmed punches, Monk's fists, Dragon Survival bites and claws, and pickaxes** should hurt Angels; ordinary swords, arrows and spells should not automatically qualify. `HurtHelper.hasPickAxe` uses damage-source player attribution and a **main-hand item test**, not any block-breaking event. `PICKAXE_AND_GENERATOR` rejects empty-hand strikes. A tag-only solution does not cover empty hands or form-specific attacks; `ANYTHING` alone is overpermissive. Preserve generator attacks and administrative void-death exception. Before implementation inspect actual Dragon Survival/Monk damage source attribution and test for the false-positive case where spell damage is attributed to a player with empty hands or holding a pickaxe. Prefer scoped compatibility damage filtering in the appropriate engine rather than a broad upstream rewrite. **Do not apply proposed `ANYTHING` alone as the final rule.**

**Structure-only spawning under active discussion, not yet locked:** remove ambient Angel biome spawning via a datapack override to the mod's NeoForge `angel_spawns` biome modifier (native `neoforge:none` is a possible exact-version mechanism) or a complete replacement of the mod's spawn-biome tag; preserve Angels in deliberately curated structures. Placed `weeping_angels:statue` blocks are inert until **redstone-powered** (verified from `StatueBlockEntity.tick`) and then replace themselves with living Angels. A hidden tripwire/pressure plate/sculk-sensor trigger can create proximity-based reveal in hand-authored structures **without new entity AI code**, although those triggers detect particular player actions rather than arbitrary radius. The existing Snow Angel block reveals on player collision, not distant detection. If *strict* structure-only means no ambient snow Angels, set the separate `[snow_angels].snow_angels=false` after owner direction. Native catacomb worldgen can stay; audit templates for entities/spawners and structure-set frequency.

**Claimed-chunk idea:** FTB Chunks protection cannot be assumed to suppress natural or statue-activated mobs. An optional Angel-specific claim-state check at **activation/spawn time** could stop pre-generated dormant statues in claims, but requires exact FTB Chunks API review and a carefully limited implementation. Note that claims can be placed *after* structures generate; structure-only spawning does not mean claim safety. Do not disable hostile spawns globally or modify other mods' structure encounters. For first pass, prefer structure-only spawns as the main policy, with claim blocking as a separate defense if actually desired. Manual summon/spawn eggs and test commands must remain possible for QA.

**Upstream evidence:** [`StatueBlockEntity`](https://github.com/Jeryn99/Weeping-Angels/blob/mc/1.21/common/src/main/java/mc/craig/software/angels/common/blockentity/StatueBlockEntity.java), [`SnowAngelBlockEntity`](https://github.com/Jeryn99/Weeping-Angels/blob/mc/1.21/common/src/main/java/mc/craig/software/angels/common/blockentity/SnowAngelBlockEntity.java), [`HurtHelper`](https://github.com/Jeryn99/Weeping-Angels/blob/mc/1.21/common/src/main/java/mc/craig/software/angels/util/HurtHelper.java), [NeoForge 1.21.1 biome modifier docs](https://docs.neoforged.net/docs/1.21.1/worldgen/biomemodifier/). Source-level only; confirm pinned artifact and effective datapack behavior.

| `[damage].hurt_type` | PICKAXE_AND_GENERATOR | **Target physical-only filter, implementation pending** | Permit punches, Monk fists, bites/claws and pickaxes; reject ordinary swords/arrows/spells. Native config alone cannot express it. |

**Earlier ambient-spawn fallback, now lower priority:** natural Overworld-only spawns were proposed, but owner is exploring **structure-only encounters** instead. If structure-only is approved, suppress the regular biome modifier entirely rather than attempting an exhaustive natural-spawn dimension blacklist. Keep destination blacklist independent. Treat Snow Angel worldgen separately.

**Damage implementation gate:** `ANYTHING` alone is no longer a recommended final setting because it lets swords, arrows and spells hurt Angels. Native pickaxe checking also rejects empty-hand and form-based attacks. Implement and test a selective incoming-damage policy against exact pinned sources before changing the native damage setting.
