## Source-backed investigation / hypotheses, not player-proven causes

1. **Ascension timing / JAWR blood initialization and HUD**. Current bridge invokes `afterJAWRSetLevel()` on JAWR `VampireLeveling.setLevel` return, and redirects Vampirism feeding to JAWR when dual. JAWR native `increaseLevel` initialization may not yet be complete. The `VampirismBloodBarMixin` intentionally hides Vampirism's overlay when JAWR level >0; absence of JAWR HUD makes both pools invisible. Capture native JAWR max/current, Vampirism max/current and dual state *before upgrade, immediately after, after feed, and after relog*. Fix native state ordering and client synchronization without creating a synthetic blood pool or a polling-every-item workaround.
2. **Sea sushi**. `kubejs/data/dragonsurvival/data_maps/dragonsurvival/dragon_species/diet_entries.json` already lists `aquaculture:sushi` with nutrition 6/saturation 5. Verify runtime item ID, data-map application, alternate datapack priorities and food-use behavior rather than adding a duplicate.
3. **Forest magic foods**. Explicit datapack contains `minecraft:enchanted_golden_apple` and `minecraft:golden_carrot`, but no validated enchanted golden carrot mod ID or `ars_nouveau:sourceberry` entry. Check actual registry IDs and evaluate the previously agreed universal magical-food exception for hunger-using forms without admitting grain/cooked meals.
4. **Monk skill purchases**. `MonkSkills` registers native Vampirism skills and a level skill tree with a faction unlock predicate. Despite successful mastery ranks, the in-game purchase UI denied access. Validate faction/client sync, `SkillPointProviders` and the exact Vampirism unlock predicate against pinned native behavior; do not award skills by bypassing server-side checks.
5. **Monk noncombat training**. `MonkMasteryEvents.onBlockDrops` awards +1 for an empty-tool break of tagged training blocks per `BlockDropsEvent`, and +8 the first time an edible food ID is discovered. A single Treecapitator event represents one action. Spell mining needs explicit owner-attribution + successful-break events, not per-tick nearby-block scans; no mana-free exploit.
