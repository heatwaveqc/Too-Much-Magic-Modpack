**Scope/evidence:** source-backed analysis of base Ars Nouveau at immutable upstream commit [`4d323fba`](https://github.com/baileyholl/Ars-Nouveau/tree/4d323fba9200c3293a4f4848cf1e0fe70beb7098). ## I. Actual cost pipeline (three distinct questions)

1. **The glyph's default/configured price.** [`AbstractSpellPart.getCastingCost()`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/spell/AbstractSpellPart.java) returns the loaded per-glyph `general.cost` config, falling back to its `getDefaultManaCost()` only if the config field is absent. The spell tier likewise uses configured `glyph_tier`, not just a Java declaration. The source's 67/5/13 tables index **defaults**, not pack-effective values.
2. **Complete spell's nominal price.** [`Spell.getCost()`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/spell/Spell.java) walks the entire ordered recipe. Every non-augment (cast method/effect) adds its configured casting cost. Each augment adds [`augment.getCostForPart(augmentedPart)`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/spell/AbstractAugment.java), with the **most recent preceding non-augment part** as its target. That part can define `augment_cost_overrides`; otherwise the augment's own configured/default price is used. A list of augment glyphs is therefore **not** a global multiplier, and the same augment may cost differently on different action parts.
3. **Actual affordability and expenditure.** [`SpellResolver.getResolveCost()`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/spell/SpellResolver.java) calculates nominal cost minus [`ManaUtil.getPlayerDiscounts`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/util/ManaUtil.java) from eligible Curios/worn items/armor/caster tool, posts `SpellCostCalcEvent.Pre`, then clamps at zero. On successful cast, `getExpendedCost()` independently recalculates nominal minus equipment discounts and posts **`SpellCostCalcEvent.Post`**, then clamps to zero. It passes the final amount to the caster's payment method. **Pre availability and Post spending are separate event routes**; don't claim their values are identical once addon/TMM event listeners are active. The event class contains a mutable `currentCost` ([source](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/event/SpellCostCalcEvent.java)).

**Ordering/failure:** `SpellResolver.canCast` validates the spell and checks affordability first. Each top-level cast path then posts cancellable `SpellCastEvent`; the form's result determines whether mana is expended (`SUCCESS`) or not (`FAILURE` / `SUCCESS_NO_EXPEND`). Native turret (`TileCaster` with `TURRET` type) returns from `expendMana` without that player-mana debit; this **does not imply** an automated Source/charge mechanism elsewhere is free. The chosen form may be invoked via on-use, on-block, or on-entity, with different success states. Source Jar is **not** the personal mana store. Spellcasting mana, Scribes Table one-time vanilla XP and TMM MXP remain independent.

### Default-price worked examples (before discounts, active configs, hooks and device substitutions)

| Spell phrase in book order | Form base | Effect base | Augment base (its target) | Source-default whole spell | Unlock/operation |
| --- | ---: | ---: | ---: | ---: | --- |
| **Touch → Break** | 5 | 10 | 0 | **15 mana** | Tier-I starter cast on an actual block; Touch's bare `onCast` returns `FAILURE`, so demonstrate target interaction |
| **Projectile → Break** | 10 | 10 | 0 | **20 mana** | Tier-I projectile, only resolves when projectile hits valid block/entity |
| **Touch → Break → Amplify** | 5 | 10 | 20 (Break) | **35 mana** | Tier-I Amplify improves eligible Break harvest tier; hardness, claim checks and blacklist still apply |
| **Touch → Break → AoE** | 5 | 10 | 35 (Break) | **50 mana** | Tier-II AoE adds surrounding target blocks, not unlimited area; Break must be able to harvest each block |
| **Projectile → Pierce → Break** | 10 | 10 | 40 (Projectile) | **60 mana** | Tier-II Pierce modifies projectile behavior, **not** Break, because it follows Projectile |

These numbers are arithmetic from the exact 5.13.5 Java defaults, assuming **no per-action augment price override for the listed pair, no configured price overrides, no event adjustments and no caster discounts**. They are *examples*, not measured runtime outcomes or claims of a particular player's maximum mana. Illustrative ingredient/learning-glyph costs must be drawn separately from the [133 base+addon learning recipes](ars-nouveau-glyph-recipes.md) and addon indexes.

## II. Validators are not a single rule applied identically at every stage

[`ArsNouveauAPI`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/ArsNouveauAPI.java) exposes **two** standard validators: `StandardSpellValidator(false)` for crafting/UI and `StandardSpellValidator(true)` for casting. [`StandardSpellValidator.java`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/StandardSpellValidator.java) lists their exact composition.

| Constraint | Crafting validator | Cast-time validator | Implication for instruction |
| --- | --- | --- | --- |
| At most one cast method | Yes | Yes | No double-Form spells |
| Nonempty recipe | Not independently enforced by this validator | Yes | A blank recipe cannot cast |
| Cast method must be first | Not required (item can supply a native built-in form) | Yes | In the normal spellbook, start with Touch/Projectile/etc; specialized carriers may differ |
| Augment belongs to compatible form/effect | Yes | **Not** rechecked | Craft a valid spell; don't imply casting enforces identical compatibility rules |
| Per-action augment count `augment_limits` | Yes | Only if `spell_casting.enforceCapOnCast` | Default **true** in source's ServerConfig; loaded TOML still governs |
| Per-glyph `per_spell_limit` | Yes | Only if `spell_casting.enforceGlyphLimitOnCast` | Default **true** in source's ServerConfig; some manipulators reset selected counts |
| `invalid_combos` on glyphs | Yes | **Not** rechecked | Deliberately distinct construction/legacy-spell compatibility |

[`SpellPhraseValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/SpellPhraseValidator.java) partitions each Form/Effect followed by its augments. [`AugmentCompatibilityValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/AugmentCompatibilityValidator.java) checks the per-part `compatibleAugments` collection, which addons can extend; this is more authoritative for constructed combos than just the base Java default list. [`ActionAugmentationPolicyValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/ActionAugmentationPolicyValidator.java) handles per-form/effect augment caps. [`GlyphOccurrencesPolicyValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/GlyphOccurrencesPolicyValidator.java) handles per-spell glyph counts, with special `IContextManipulator` bypass handling. [`InvalidCombinationValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/InvalidCombinationValidator.java) handles incompatible glyph combinations; these are not the same as one-action augment compatibility.

**Tier and learning:** [`GlyphMaxTierValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/GlyphMaxTierValidator.java) is invoked specially in the spellbook GUI, rather than being one of the cast-time standard validator's entries. [`GlyphKnownValidator`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/common/spell/validation/GlyphKnownValidator.java) checks player knowledge plus default-starting glyphs in its own context. Therefore don't collapse book-tier acquisition, glyph learning, construction validity and actual successful cast into a single achievement.

## III. Capacity and recovery are a separate progression track

[`ManaUtil.calcMaxMana`](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/util/ManaUtil.java) starts with `baseMax + glyphBonus × glyphmax + bookTier × tierMax`; default server configuration initializes these values at **100**, **15** and **50** respectively, then applies attribute modifiers, `MaxManaCalcEvent` and a **reserve fraction** (familiars may reserve some mana). `getManaRegen` separately derives `baseRegen + glyphBonus × glyphRegen + bookTier × tierRegen` (source defaults **5**, **0.33**, **1**), then attribute adjustments and `ManaRegenCalcEvent`. Do not advertise those as currently effective TMM numbers, and don't convert this into block Source per second. See [ServerConfig.java](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/setup/config/ServerConfig.java) and [ManaUtil.java](https://github.com/baileyholl/Ars-Nouveau/blob/4d323fba9200c3293a4f4848cf1e0fe70beb7098/src/main/java/com/hollingsworth/arsnouveau/api/util/ManaUtil.java).

## IV. Quest-source handoff (no runtime FTB changes)

1. **Novice / AR-02:** teach `Touch → Break` on a harmless breakable block, compare held mana before/after; the existing book task still checks the book, **not** a completed cast. This is the entry-level 15-mana source-default example.
2. **Scribes / AR-03:** teach a glyph's native inputs/27–55–160 **vanilla XP** learning route; explicitly consume/read the resulting glyph before using it in a spell. A possession task cannot establish learned status.
3. **Apprentice / AR-08:** one chosen Tier-II AoE example `Touch → Break → AoE`, source-default 50 mana; an instructional comparison with Tier-I `Touch → Break` is enough. Do not force all 39 Elemental add-on glyphs or create a mandatory spellbook branch.
4. **Automation / AR-17 and spell turret:** explain that automated caster success and an individual's mana drain are **not** the same accounting route. A turret action may require distinct block Source/stored power; trace exact device-specific charges before assigning energy rewards or MXP.
5. **Cross-cast / AR-31–32:** owner reports Ars 'n Spells mana is **functioning**. Teach native Loom, binding, transcription and functional cross-casting; no design hold or speculative rebalance. Separate an actual TMM-owned cross-cast/MXP regression from ordinary upstream tutorial writing if observed or if the bridge code is changed.
