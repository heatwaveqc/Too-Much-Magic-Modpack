# Neo Vitae 1.1.54 — complete eighteen-Sigil behavioral inventory

**Evidence:** Neo Vitae 1.1.54 source [`501a8d6a0431ed8aeb19e18be2e83f1856f29a21`](https://github.com/breakinblocks/NeoVitae/tree/501a8d6a0431ed8aeb19e18be2e83f1856f29a21), complete 18-item declaration list from `NVItems.java` and [registered operation inventory](neovitae-operations.md); the source [14-entry `sigil_stats.json`](https://github.com/breakinblocks/NeoVitae/blob/501a8d6a0431ed8aeb19e18be2e83f1856f29a21/src/generated/resources/data/neovitae/data_maps/item/sigil_stats.json) supplies numeric defaults for those 14 IDs, **not all 18**. [`SigilEffects.java`](https://github.com/breakinblocks/NeoVitae/blob/501a8d6a0431ed8aeb19e18be2e83f1856f29a21/src/main/java/com/breakinblocks/neovitae/api/sigil/effects/SigilEffects.java) declares 14 **shared effect *types***, not 18 individual objects: Water+Lava reuse `PlaceFluidSigilEffect`, Divination+Seer reuse `DivinationSigilEffect`, while Holding and Damned have specialized Item implementations. The full recipe/acquisition inventory remains [48 Array recipes](neovitae-array-recipes.md) and [Hellfire recipes](neovitae-hellfire-forge-recipes.md), not deducible just from registry names.

**Activation mechanics:** In the current 1.1.54 native `SigilItem.java`, *toggled* sigils are turned on/off with sneak + air-use, debit owner Anima on their configured drain interval (and turn unusable when not funded), then invoke effect active tick. One-shot Sigils debit on successful use; failed use typically does not complete the action. `NVAttributes.SIGIL_COST_REDUCTION` can change effective debit. Creative players have selected cost exceptions; do not infer standard survival cost from creative admin tests. [SigilItem source](https://github.com/breakinblocks/NeoVitae/blob/501a8d6a0431ed8aeb19e18be2e83f1856f29a21/src/main/java/com/breakinblocks/neovitae/common/item/sigil/SigilItem.java), [legacy ItemSigilToggleable](https://github.com/breakinblocks/NeoVitae/blob/501a8d6a0431ed8aeb19e18be2e83f1856f29a21/src/main/java/com/breakinblocks/neovitae/common/item/sigil/ItemSigilToggleable.java). **`lp_cost` is a native legacy field label for the EV-denominated Anima debit**, not separate Experience or MXP.

## Source corrections and player walkthrough notes

1. **Ritual Magnetism is not Sigil Magnetism.** `RitualMagnetism` is a real below-ground ore quarry; `SigilMagnetism` is portable item **and vanilla-XP-orb** pickup. `RitualZephyr` gathers loose items/XP into chest/owner. They are three separate quests/capabilities.
2. **Native default pickup radius:** `MagnetismSigilEffect.DEFAULT_RANGE = 5` and the current generated `sigil_stats.json` has `range:5`; the older 1.1.54 wiki paragraph says 7, which should not be repeated as current source default. Effective loaded sigil type data or TMM override could still change this number.
3. **Holding isn't a generic pack:** exactly **five Sigil slots**, container-bound to original item data; it delegates the currently selected Sigil's actual effect and still incurs that effect's normal costs. No collision with pack's excluded generic backpacks solely because it has a specialized 5-slot Sigil inventory.
4. **Damned is a passive binding-dependent item**, with on-kill healing and multiple attribute modifiers, separate from the generic effect-type registry. Its attribute bonus magnitudes are source values, not guaranteed apparent percent change in every final attribute formula.
5. **Strong quest proof:** binding Teleposer, actually depositing fluid, a fluid-source cleanup, player movement effect, created ephemeral bridge, returned/resurrected pet, or successfully opened storage proves the operation more honestly than possession of a Sigil. No FTB per-player detector is assumed currently authored; genuine player activation can be a manual lesson or owner-built advancement adapter.
6. **Finite source-vs-game boundary:** source registration, native recipe IDs, source defaults, effect logic and 40 draft quest teaching intentions are known. Installed 1.1.54 JAR bytes, effective datapack edits, Curios/sigil slots and client HUD/UI success are **not proven** by this document.
