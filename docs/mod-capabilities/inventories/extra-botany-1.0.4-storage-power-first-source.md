# Extra Botany Revived 1.0.4 — source-first storage, resource and registration audit

**Status:** source-backed **partial**, not the full addon capability Atlas. Exact TMM artifact [ExtraBotany 1.0.4 SHA-1 pin](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/blob/test/full-integration/mods/extra-botany-revived.pw.toml); upstream [immutable source commit b58857d3](https://github.com/Velron-Devs/Extra-Botany-Revived/tree/b58857d3658479f6e8684d3b45f6d3138a294548) and [Gradle dependency floor](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/gradle.properties) require Botania Revived 2.0.2+. This is a distinct `extrabotany` mod; do not conflate it with the base `botania` namespace. No new JAR binary parity or installed config assertion.

- The [config specification](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/java/velrondevs/extrabotany/config/ExtraBotanyConfigSpec.java) has standalone `manaGenerator` (**Flux Manafield**, default enabled; **40,000 FE** buffer; default **1,000 FE→99 Mana**; **200 Mana/t** output setting), and `manaLiquefaction` (**Mana Liquefaction Device**, default enabled; **1,000,000** internal Mana capacity; Fluided Mana tank IO and redstone-switched transfers). These are **defaults and config descriptions**, not yet a proven converter round-trip, active TMM config or credited actual transfer rate.
- The same config has a **Gaia III combat disarm** check (default enabled) and optional `relicsNeedEgoDefeat` (default **false**). **Do not claim every Ego-gated relic is enforced** when this option defaults false. Preserve separate Ego/Void Herrscher summon checks until their classes are researched. This is a potential TMM gate/gear-balance review, not an owner design decision already inferred from defaults.

## Concrete policy conflict: Mini Handbag (existing TMM issue #16)

**This is real portable item storage, not a decorative trinket.**

- [`MiniHandbagItem`](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/java/velrondevs/extrabotany/common/item/MiniHandbagItem.java) exposes **24 internal slots** through `ItemBackedInventory`; right-click opens its portable inventory; direct item-over-item interactions also delegate to Botania `InventoryHelper`. On destruction its contents are scattered, not intentionally deleted.
- [`MiniHandbagMenu`](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/java/velrondevs/extrabotany/client/gui/handbag/MiniHandbagMenu.java) has **four extra armor UI slots which actually map to the player's existing armor equipment**, not 4 more bag inventory cells. The 24 bag slots are ordinary `new Slot(bagInv,...)` without a `mayPlace` bag filter; `quickMoveStack` forwards from player inventory to this unfiltered 24-slot range. The parent [Botania `ItemBackedInventory`](https://github.com/Velron-Devs/Botania-Revived/blob/5f803227d484598da1f1093a91d5d7cf5cf9600d/src/main/java/velrondevs/botania/common/item/ItemBackedInventory.java) is a `SimpleContainer` backed by ItemStack NBT and likewise does not impose a bag-nesting eligibility rule.
- [Native shaped recipe](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/generated/resources/data/extrabotany/recipe/mini_handbag.json) is **six leather, two Spirit Fragments, one chest** (`ABA/ACA/AAA`; A leather, B Spirit Fragment, C chest). This is a real survival craft, not creative-only. No tested installed TMM override was established in this research pass.
- TMM [#16](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/issues/16) **already requires a comprehensive cross-mod no-bag-in-bag filter before survival release**, for direct, quick-move, shift-click and automation paths. Extra Botany adds a distinct destination and source bag: `extrabotany:mini_handbag` must be included in `#tmm:portable_bags` if kept and its internal slots/server handler protected *before* insertion. A tag alone **does not** make its stock Slot reject anything. Existing vanilla shulkers/bundles and other eligible portable bags likewise need denial in Mini Handbag destinations.
- TMM's separately recorded design preference rejects **generic backpack/storage additions**. Keeping Extra Botany the mod does *not* automatically approve this portable item. Integration owner should determine whether to **disable Mini Handbag survival acquisition** (and ensure no loot/shop/quests grant it) or explicitly allow it as a bounded exception *and* implement the #16 no-nesting guard. **Do not remove Extra Botany as a whole to solve one item.** No owner decision is inferred here.

## What research is still open

1. **Bosses:** Gaia III, Ego, Herrscher of the Void exact summon-item/structure/achievement predicates, loot, permanent owner attribution and disarm rules.
2. **Generated flower operations:** each addon generator's native input/output cycle, cost, cooldown, range and configured amount; classify functional flowers separately from generators.
3. **Resource routes:** inspect real Flux Manafield and Mana Liquefaction implementation before asserting an exploit, free conversion, Fluided Mana ↔ item component equivalence, or round-trip efficiency. Existing Botania Revived Mana Fluxfield consumes **1 Mana→10 FE**; config defaults for the *other direction* suggest **1,000 FE→99 Mana** (slight theoretical loss), but effective implementation and all intermediate conversions are not yet proved.
4. **Mini Handbag release integration:** check current branch/tag/config/loot for actual suppressions, then either exclude item or add narrow early insertion denial and cross-mod tests. This is **pack integration**, not an Atlas runtime code task.

No native gameplay, QA package, Packwiz index, FTB chapter, item blacklist, server/client, or module code changed by this research.
