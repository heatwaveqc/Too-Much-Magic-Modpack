### TMM policy versus deployed config: crucial distinction

TMM [`docs/RESOURCE-ECONOMY-STANDARD.md`](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/blob/test/full-integration/docs/RESOURCE-ECONOMY-STANDARD.md) locks **20 Botania Mana/EMC** and **200 FE/EMC**, equivalent to **10 FE/Mana**. It also specifically says *keep Botania Mana Fluxfield at 10 FE/Mana*. This is an **economy valuation**, not proof that every conversion path is configured as an exact reversible adapter; loss is legitimate.

On the inspected **`test/full-integration`** branch, the repository lists no `config/extrabotany-common.toml`, `defaultconfigs/extrabotany-common.toml`, or `config/botania-common.toml`; none of the current KubeJS server scripts was named as an Extra Botany energy override. The earlier Alkahestry/Botania Batch 4 PR [#342](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/pull/342) changes **conjuration recipe economy**, not the FE→Mana config. **No specific user-approved Extra Botany override rate/deployment evidence was recovered.** Expected config starting point is **upstream 99 Mana/1,000 FE**, but an actual generated world/serverconfig or independent mod override still requires inspection before asserting `verified_in_pack`. Do not label it “never configured anywhere”; the source-backed conclusion is **no tracked extra override**.

**Design consequence:** no new decision needed to retain the native 1%-loss conversion. If owner later wants exactly lossless 1,000 FE→100 Mana, flag round-trip economics explicitly before modifying; **do not silently change defaults based on valuation ratio**.

## Source-backed Voidcaller craft and Hero Medal provenance

Earlier generated-only recipe searches missed **handwritten** recipes under `src/main/resources/data`. [`extrabotany:voidcaller` native recipe](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/resources/data/extrabotany/recipe/voidcaller.json) is a standard **3-output shaped craft** (`ASA / PHP / ASA`): **4 Life Essence (A), 2 Shadowium (S), 2 Photonium (P), 1 Hero Medal (H)**. Its [Lexica entry](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/resources/assets/botania/patchouli_books/lexicon/en_us/entries/extrabotanies/voidcaller.json) links the same recipe; the [native recipe advancement](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/resources/data/extrabotany/advancement/recipes/misc/voidcaller.json) unlocks when Hero Medal is held.

**Where Hero Medal enters the chain:** the addon [Pandora's Box reward bag loot generator](https://github.com/Velron-Devs/Extra-Botany-Revived/blob/b58857d3658479f6e8684d3b45f6d3138a294548/src/main/java/velrondevs/extrabotany/datagen/providers/loot/RewardBagLootProvider.java) includes **one guaranteed Hero Medal** as its final fixed pool, alongside other rewards. Native player-owned **Gaia III/Ego** boss loot can grant Pandora's Box when `botania:enable_relics` permits. Thus the **intentional** endgame path is **Gaia III/Ego → Pandora's Box → Hero Medal → Voidcaller → Herrscher** with native costs; sources other than those boss drops may also yield medal through reward bags, so don't turn it into a hard first-kill requirement without checking the effective loot graph.

This resolves the prior uncertainty about whether the final boss had a survival summon recipe. **Not** a loaded in-game PASS; crafting, relic enablement and reward-bag loot table require installed data verification.

## Source-closure boundaries and required follow-ups

- Exact **Nature Orb charging pedestal/energy transfer**, all weapon/Curios, original flight gear and all addon flowers require separate catalogue. The three bosses are **behavior and summon-source mapped** but are **not** gameplay PASS.
- In the completed quest-source map, never make the player obtain `Core of the Void` as a guaranteed reward from one Herrscher kill: native chance is 2% per eligible loot-table invocation.
- Native configuration and default conversion do not require a new design decision; any custom TMM tuning belongs to the integration/economy owner and actual live file. No pack files outside this Atlas docs folder were changed.
