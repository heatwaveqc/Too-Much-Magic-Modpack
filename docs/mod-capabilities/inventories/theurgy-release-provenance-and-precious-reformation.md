# Theurgy 1.79.0 — release provenance and precious-item acquisition audit

**2026-11-21 follow-up.** TMM pins Theurgy NeoForge 1.21.1 version **1.79.0**, Modrinth `EBO0aQOY`, SHA-512 `2e92aa0a3462d400feed398d4a675f9492dab3613ad698f24fcbcce34b565a079a7362fb637c4e268dbb71be5d11fc6630758f149ecccc8d6603f2e9d96f0569`; see [Packwiz record](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/blob/test/full-integration/mods/theurgy.pw.toml). **Method:** version-tagged source, generated recipe JSON, Java matcher and release workflow. **Not performed:** direct JAR byte/hash inspection, client launch, loaded TMM datapack audit or native gameplay testing.

## 1. Version discrepancy resolved at release-build level

The [upstream tag `release/v1.21.1-1.79.0`](https://github.com/klikli-dev/theurgy/tree/release/v1.21.1-1.79.0) still has `mod_version=1.47.1` in [gradle.properties](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/gradle.properties). This is a **development fallback**, not the release version. The [Build and Publish workflow](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/.github/workflows/build_and_publish.yaml) triggers on `release/v**` **tags**, parses the version suffix from the Git tag, passes it into the build through environment variable **`MOD_VERSION`**, and publishes the versioned JAR to Modrinth. [build.gradle](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/build.gradle) overrides `mod_version` with this environment variable and uses it in archive/version/manifest metadata. Its Modrinth artifact naming aligns with TMM's pin.

[Source comparison: 1.78.0 → 1.79.0](https://github.com/klikli-dev/theurgy/compare/release/v1.21.1-1.78.0...release/v1.21.1-1.79.0) shows **six commits ahead, zero behind**, with changes limited to workflow/release housekeeping, translated language, `EntityUtil.java` client-only IDs, and removed generated Gradle caches. **No recipe-provider Java, generated recipe JSON, sulfur registry, Reformation matcher or data tags changed** across those refs. A stale `CHANGELOG.md` header also does not invalidate the tagged build.

**Provenance conclusion:** the 1.79.0 release-tag source and its published build workflow match the pinned artifact version and explain the stale fallback. **The published binary itself was not downloaded/unpacked**, so no byte-for-byte parity certification is claimed; reopening this as a broad native-gameplay blocker is unwarranted.

**The target is a real existing item.** [`ReformationRecipe.matches`](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/main/java/com/klikli_dev/theurgy/content/recipe/ReformationRecipe.java) rejects a recipe unless its target ingredient matches **`getTargetPedestalInv().getStackInSlot(0)`** and sufficient Flux is available; it then checks each source pedestal. [`ReformationArrayCraftingBehaviour.craft`](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/main/java/com/klikli_dev/theurgy/content/apparatus/reformationarray/ReformationArrayCraftingBehaviour.java) consumes **sources and Flux, not the template target**. The in-game [Hermetica Target chapter source](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/main/java/com/klikli_dev/theurgy/datagen/book/gettingstarted/reformation/TargetEntry.java) explicitly instructs players to put a target Sulfur in the pedestal and says it is returned/not consumed.

[`SulfurMappings.noAutomaticRecipesFor`](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/main/java/com/klikli_dev/theurgy/datagen/SulfurMappings.java) **excludes Star and Egg Sulfur from general automatic conversion recipes**, even though the explicit, sample-gated recipes above exist. The initial `noAutomaticRecipesFor = Set.of()` declaration in `ReformationRecipeProvider` is overwritten by this real exclusion set before recipes are generated. Therefore the previous Atlas inference that “empty exclusion set” might permit anonymous Star/Egg generation was incorrect.

[Digestion](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/generated/resources/data/theurgy/recipe/digestion/alchemical_niter_mobs_precious_from_rare.json) can generate **one Precious Mob Niter** for **16 Rare Mob Niter + 1 Purified Gold + 50 mB Sal Ammoniac**. A [64 Precious Gem Niter → 1 Precious Mob Niter Reformation recipe](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/generated/resources/data/theurgy/recipe/reformation/alchemical_niter_mobs_precious.json) also exists, but critically **requires existing Precious Mob Niter in the target pedestal**. Neither alternate input makes an absent Star/Egg Sulfur target appear.

## 3. TMM impact and closure

**No native-source first-kill bypass through these chains.** To acquire the first Star/Egg Sulfur via the inspected standard route, the player needs the original Star/Egg item. After that, duplication through Niter/Flux/Incubation is *intended* expensive high-magic replication. This is consistent with TMM's already approved ability to reproduce acquired boss drops. It does **not** prove an advancement or first-kill event happened: FTB quests must detect the actual first kill separately where required.

**Iesnium likewise sample-gated:** the [precious Metals Niter→Iesnium Sulfur recipe](https://github.com/klikli-dev/theurgy/blob/release/v1.21.1-1.79.0/src/generated/resources/data/theurgy/recipe/reformation/alchemical_sulfur_iesnium_from_alchemical_niter_metals_precious.json) uses a target Sulfur sample, and is tag-conditional. Uranium remains intentionally unrestricted. No direct Draconium/Deepslate Replica Ore sulfur route was established; Occultism's first miner tier for those remains Afrit/Marid.

**Remaining boundaries, not design blockers:** We have **not** inspected binary JAR contents or effective TMM loaded recipes/tags, and no TMM recipe overrides were authored here. Reopen source research if the pin or source changes, or a concrete loaded data difference emerges. TMM changes to material eligibility, cross-mod acquisition or per-player first-kill quest triggers get the usual targeted QA; no standalone native regression suite is necessary for this Atlas source closure.

**Assessment:** Theurgy's 29-axis Atlas and 20 research-only instructional lessons are **source-research-complete for quest authoring**, with clear release-provenance and runtime boundaries. Move to the next mod.
