## Distinct capabilities, not interchangeable features

**Pack experience rule (owner-confirmed):** **Vanilla XP does not grant MXP.** **Tome of Peritia** is Neo Vitae's **vanilla XP storage item**: when placed in **slot 0 of a compatible chest or item handler directly above The Gathering's Master Ritual Stone**, The Gathering collects nearby vanilla XP orbs and deposits that XP into the Tome. It neither stores MXP nor converts XP to MXP. Do not treat the Tome's contents, collected XP orbs or the act of collection as a skill-progression trigger.

## Teachable first-to-endgame farm chain

1. **Early, no ritual required:** Inscribe Repulsion (hostile mobs only) or Collection Array (drops in 2 blocks); demonstrate physically moving one safe target and collecting one dropped item without attributing either to a kill.
2. **Tier-I array movement:** Acquire Tabula Robur and Blood Pearl; make the Vortex Sigil (base before catalyst). Pull an eligible hostile toward a protected collection/kill area. Show redstone pause, the player's immunity with an Orb, and the optional **Tabula Rasa player exclusion** without asserting all creatures are affected identically.
3. **Tier-II ritual loot/XP:** Build and activate **The Gathering** (`zephyr`) with a chest directly atop its Master Ritual Stone. Guide the player through dropped-item capture from the documented range and explain overflow behavior. Then teach the distinction between mob item drops and **vanilla XP orbs**: a **Tome of Peritia** in chest slot 0 stores the XP the ritual collects. These are native features to teach, **not standalone upstream functionality tests**. Document outside-range and owner/Anima conditions without requiring an extra QA run.
4. **Combine with actual harvest:** Build a safe mob generator, align Vortex/Repulsion/Containment to route entities into a legitimate killing or Spiritus/EV-harvest mechanism (Spike Array or ritual Well of Suffering). The Gathering handles **item drops/XP after a real death**, not the creatures. Distinguish Well's EV into network/altar from dropped Spiritus and ordinary items. **Vanilla XP, whether collected directly or stored in the Tome of Peritia, does not grant Tyz MXP.** Any MXP granted by a separately qualifying kill/action is independent of the collected vanilla XP.
5. **Upper end:** Contrast the entity-heavy Well/Spike/collection arrangement with **Torment Nexus**, which can simulate spawner harvest for EV *without spawning actual mobs*. A no-entity simulation does **not** provide ordinary physical drop/XP entities for The Gathering to collect unless a separate source explicitly creates them. Check anti-boss-farm, chunk and spawner exclusions in TMM.

## Name and cross-mod disambiguation

- Neo Vitae's **Vortex Sigil** and **Repulsion Array** are the *native persistent push/pull glyph-like effects* in this dossier.
- **Ars Nouveau** separately has `ars_nouveau:glyph_pull` (a cast effect, not the same as a passive Vortex Array). A third-party **Ars Zero** addon exposes a Push glyph in some 1.21.1 reference catalogs, but it was **not found in TMM's `manifest/mods.json`** at the inspected baseline. Do not attribute that addon glyph to Neo Vitae or promise its presence in the pack. The actual installed Ars glyph/spell list and cross-mod farming interactions should be verified in the independent Ars dossier.

## Acceptance boundaries — TMM changes only; no native feature re-testing

**Owner QA scope (2026-11-21):** The source-backed Neo Vitae **Gathering, Tome of Peritia, Vortex, Repulsion, Containment, and Expulsion** are upstream mechanics. **Do not schedule standalone in-game acceptance tests to prove those features work when TMM has not changed them.** A documented native walkthrough or player quest exercise is not an obligation to regression-test an upstream implementation. In particular, **do not test whether Tome of Peritia stores vanilla XP**: that is accepted native functionality, and collecting/storing vanilla XP **does not award MXP**.

Only add a targeted in-game test when there is a **specific affected TMM implementation or observed failure**, for example:

- A new TMM FTB quest or first-party event/advancement detector: verify **that task credit** follows its promised action (and its player/team permissions), not that vanilla item/XP collection exists.
- A TMM KubeJS/Java/config modification affecting mob loot, XP, inventory interfaces, entity movement or ritual resource debit: check the changed interaction and its narrow boundary, not a full native-feature matrix.
- A TMM cross-mod adapter or observed integration failure involving modded spawners, Ars Containment Jars, FTB claims, Neo Vitae EV/Spiritus or Tyz MXP: reproduce **the changed cross-mod behavior** and verify the specific fix. There is no independent XP→MXP compatibility experiment to perform.
- Planned survival gates / boss-farming rules: test only the **TMM-owned gate or blacklist** if it actually applies to one of these native farm mechanisms.

**Current work status:** This Atlas change only documents upstream capabilities; no Neo Vitae farm function or Tome integration was modified. Therefore **there is no gameplay QA item for native Gathering or Tome operation**. All values here are source-aligned to 1.1.53; no assembled-pack runtime test is claimed.
