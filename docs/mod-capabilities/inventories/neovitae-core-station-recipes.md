## Tabula Vitae — precise orb-tier and Anima demands

`upgradeLevel` is the **minimum Orb tier actually checked by `TabulaVitaeBlockEntity`**, not an optional amount of table augmentation: `orbTier < recipe.getMinimumTier()` blocks production. A bound Orb provides the personal Anima account; **`syphon` is total nominal EV across `ticks`**, with integer-incremental payments (source `syphonEV` calculates difference between cumulative `totalSyphon * elapsed / totalTicks` and `totalSyphon * reached / totalTicks`). Source machine checks valid recipe, Orb tier, output room and other tool readiness before charging.

## Hellfire Forge — availability thresholds are not the actual drain

A Petty Gem can require only 1 available Spiritus to manufacture, and transformations of iron tools may register 0`minDrain`/0`drain` while still requiring the specified catalyst gem. Native ingredients can require their own tier/loot/recipe gates.

**Gating consequence:** Greater Spiritus Gem needs Tabula Spiritus + Weak Blood Shard and a Demon Crystal; Grand needs Animus Mote, Tabula Aetherea and Permafrost Core. A "5 gems" quest should not assume they're unlocked purely by crafting more copies of the previous gem.

**Dungeon key economy:** Simple Key recipe uses **one Tiny Corrupted Dust**, not a full Corrupted Dust, plus two iron ingots. **Crystal Cluster** requires the four exact named inputs shown and min 2,048 Spiritus, consume 1,024, before it can serve as Tier-V altar capstone. This is a real late-game Spiritus requirement that the high-level tier table omitted.

## Crafting side-effects and truthful quest completion

- `neovitae:reagent_binding` is Tier-3 on Tabula. The Sentient Plate uses **base Binding Reagent + added iron chestplate**, an actual operation; merely having the chestplate is an inventory proxy.
- `neovitae:sentient_sword` and `sentient_pickaxe` are **Forge transform** recipes (different serializer from ordinary four-ingredient Forge recipes), and list `transformInput` plus catalyst. A recipe importer must preserve that distinction.
- `NeoVitaeCraftedEvent.AlchemyTable`, `.Forge`, `.Altar` are emitted by the respective machine codepaths (source event class; verify placement of posts in caller). These events expose actual recipe inputs/outputs but have **no player UUID**; player quest credit needs separate authorized attribution/validation. `RitualEvent.Activated` carries the player and ritual and is stronger for task proof. Neither gives an out-of-the-box FTB Quest detector in the current pack.
- Array one-off vs persistent effect, owner determination and energy payment semantics depend on effect classes, not these JSON files alone.
