### Foundation and effect inheritance
Compared Farm & Charm compile-time Foundation 1.0.7 immutable source 05f16c99ecfd0ed9a32ca6c81c125597dda3a6d3 with TMM standalone Foundation 1.1.0 source 760332e856292e457e2b5beec4054bb0ef08c0b3 (mod_version confirmed). Relevant merge rules match: IngredientEffects.getEffects reads normal/custom potion effects from PotionItem, or FOOD possible effects; it first rebuilds food without Hunger, mutating input stack. bestEffects picks highest amplifier per effect type, longest duration breaks tie; does not sum durations or amplifiers. collectMergedSortedEffects discards probabilities by returning instances. Farm & Charm pot/roaster copies only carrier-enabled output and passes 1.0 probability; existing effect types on result skipped by addEffect. Thus uncertain/chance-based food effects can become guaranteed on eligible output, and a single multi-output recipe could copy the same effect into multiple units if authored; actual usable ingredient tags and yield must be audited before calling a duplication path. Goulash is the confirmed Farm & Charm carrier, not a universal potion ingredient acceptor. IngredientEffectFoodItem.finishUsingItem explicitly applies effects on server then calls user.eat, potential double application depending on vanilla implementation (not claim of doubled duration). No generic permission to add arbitrary potion to pot or duplicate alchemy effects. FOOD rebuild preserves nutrition, saturation conversion and alwaysEdible/fast flags, but not necessarily all custom fields. EffectFoodItem and EffectDrinkItem duration constructor arguments are unused; FoodProperties effect duration is authoritative, correcting the ambiguity for oatmeal (45s) and beef patty with vegetables (240s), not300s. Tea durations remain short. Foundation FoodBlock uses food component from new block item if present, fallback registered foodComponent, applies per-bite effects, directly modifies hunger and emits EAT game event; maxBites removes block after last bite. Placed feast vs held food and special-diet interception are real pack-specific integration boundaries. Need determine exact bundled-vs-standalone Foundation class selection, not claim release binary parity.
