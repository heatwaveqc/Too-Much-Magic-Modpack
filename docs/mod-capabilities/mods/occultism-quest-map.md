# Occultism — Atlas instructional quest-source plan (research only, 2026-11-21)

**Source dossier:** [Occultism 29-axis Atlas](occultism.md). **Version:** pinned 1.21.1 NeoForge `1.227.0`, source commit [`990303ea95ba057791b7d407d6cac5151f66d799`](https://github.com/klikli-dev/occultism/tree/990303ea95ba057791b7d407d6cac5151f66d799). **Existing source-complete reference:** [native walkthrough and companions, separate PR #265](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/blob/research/mod-comprehension-local-jars-20261116/docs/mod-comprehension/mods/occultism.md). Native `Dictionary of Spirits`, 20 exact pentacle guides and JEI remain the operational source, not a reconstructed textual layout.

**TMM live chapter truth:** current `test/full-integration/config/ftbquests/quests/chapters/occultism.snbt` has **one optional checkmark** (ID `544D303000F00001`, task `544D403000F00001`), **2 vanilla quest XP and one paper**, with no Occultism instructional path. All `OC-00…OC-56` below are **57 Atlas research labels, zero created FTB quest GUIDs**, not a mandate for 57 new nodes; they describe a prospective main walkthrough plus optional role-based lessons. Authoring, coordinates, FTB criteria, cross-chapter dependencies and reward balancing belong to a separate quest implementation owner. The first 21 records form the candidate orientation/core teaching lane (some would consolidate), **36 are optional branches**. No runtime quests, rewards, config, KubeJS, scripts or mod pins were changed.

**Quest-design rules:** Always teach *the named ritual/circle, its real inputs and player action, the item/entity/event it actually emits, and one demonstrated operation*. An item task can establish possession but not the correct Source/ritual, bound component, owner, living-worker job, loaded storage link, ore generation, event kill or saved familiar. Native ritual advancement may precede successful spawn/delivery. Where FTB lacks a native detector, use a clearly labeled manual observation/acknowledgement, or defer a narrowly scoped **first-party detector** under its owner; do not forge certainty. Give **XP plus genuinely ordinary useful materials**, not hard-gated essence, Nether Star, Iesnium, Trinity Gem, boss item, restricted mineral, free bound worker or late miner. Separate realm/pack lore from actual hard unlocks. Do not rerun unmodified upstream native functions just to prove this research.

This is an **instructional progression proposal**, not a claim every optional material/ability is required by the mod's complete recipe graph. Lower-level native work and upgrades remain playable as branches.

## 4. Handoff boundaries and actual QA queue

**Documentation-ready now:** every named research task above can have source-based tutorial prose grounded in Dictionary and version-aligned Mod Comprehension. An implementation writer may consolidate these labels into fewer real quests and reuse the current orientation GUID after ownership coordination; **do not author GUIDs by copying `OC` labels**. Require only actual named critical prerequisites. Reward amounts are intentionally not selected here; names of ordinary items are examples, not committed reward grants.

**Pack-specific technical dependencies, no new game-design vote implied:** (A) inspect **loaded Foliot-accessible Draconium** recipe/tag and conditional ordinary Uranium and Eldritch Raw Uranium tags against current TMM gate decisions; (B) check Soul/Trinity/Battlefield and bound-worker transport against capture/replication blacklist implementation [#373](https://github.com/heatwaveqc/Too-Much-Magic-Modpack/pull/373), without blocking genuine native Occultism ritual work; (C) check native Ars Ocultas and Ars Unification cross-adapters **only if TMM changes the interaction or an actual bug emerges**; (D) implement truthful **first-party** per-player ritual, worker, mine and storage predicates only if a quest writer selects them; (E) protect player/team credit and reward/achievement duplication in TMM-authored tasks.

**In-game test queue only for TMM-owned changes/observed problems:** first-party changed tag/recipe/loot eligibility on Foliot/late miner, changed Boss/Trinity/Battlefield capture denial, new FTB manual/item/event predicate or quest-detection bridge, and any changed storage access/permission adapter. Those tests should include legitimate eligible positive, protected boundary, reload and item conservation where affected. The comprehensive native research already lists source-specific risks (worker insertion remainders, Calling Book release, storage menu, rare familiar states), but those are **not an automatic mandatory native QA backlog for Atlas closure**. No current client/server acceptance is claimed.

**Atlas completeness vs runtime:** This map and [dossier](occultism.md) cover major native routes across all 29 axes and reuse the source-complete 931-recipe research; they are not 931 detailed FTB criteria, not final progression rewards and not proof every loaded optional tag exists. Future pin/config changes require focused staleness review.
