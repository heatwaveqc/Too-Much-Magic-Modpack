# Bountiful specialist decree sealing — owner-requested bridge

2026-11-19. Bountiful currently has vanilla component-stamped JSON recipes for ordinary school/general decrees. Those are intentionally not sufficient for class/form decrees: a vanilla recipe lacks a player-form predicate and can be crafted in automation. The owner requires specialized decrees to be *crafted by the respective transformed/class player*, with a regular board thereafter and transferable signed decree. This source adds one reusable, server-only **application sealing** handler to the shared Progression engine, where executable discipline logic belongs.

A controlled shapeless recipe creates one `bountiful:decree` with ONLY `minecraft:custom_data` marker `tmm_bountiful_decree_application: "tmm_<family>"` (unsigned). This item has zero EMC under the separate approved ProjectE mapping PR #378. On server-side right-click, the handler verifies an exact supported family, then the joined native Progression path or current complete five-provider Transformations snapshot, and only then uses the installed Bountiful codec to attach `bountiful:decree_data` `{"ids":["tmm_<family>"],"rank":1}`; removes the token marker. If upstream absent, codec invalid, form state missing/unknown, or not eligible, it remains unsigned. No player NBT assertion, no conversion to another family, no automatic XP or form acquisition. Signed decrees transferable and usable at ordinary public boards.

Supported in this first dev target: Vampire (JAWR), Werewolf (JAWR), Goety Lich, Forbidden Magic Lich, Archlich (both), Abomination (both bloodlines and both lich providers), and joined Hunter/Monk paths. Inheritance under composites is permitted for individual provider decrees. In-progress Dragon Survival species-specific forms, Dracolich subspecies/resource provider and Gilded are deliberately **held** until authoritative current species/path APIs are confirmed. This handler must be merged/reconciled through the designated Progression writer, not copied to Bountiful or transformed-module scripts. The Bountiful draft compiler emits application recipes only when this Progression capability is specifically reviewed/enabled, and corresponding bounty pools exist.

Unit tests only inspect finite roster; runtime test must cover real game interaction and signed component codec, complete native probes, newly-joined state, fake/automation, duplicate right-click/relog, invalid marker, nonmember, form cure, and class graduation/relocation. Do not claim client acceptance or trigger full modded boot without authorization.
