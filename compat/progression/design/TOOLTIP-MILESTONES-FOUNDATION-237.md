## ProjectE Jade integration — native API / pin receipt

**Client-only implementation:** `src/main/java/io/github/heatwaveqc/tyr/progression/compat/jade/ProjecteEmcJadePlugin.java`. Jade 1.21.1 `Snownee/Jade:1.21-neoforge` exposes `@WailaPlugin`, `IWailaClientRegistration.addTooltipCollectedCallback(int, JadeTooltipCollectedCallback)`, `IBoxElement.getTooltip()`, and `ITooltip.get/remove(ResourceLocation)`. `BlockAccessorClientHandler.gatherComponents` calls `ElementHelper.setCurrentUid(provider.getUid())`, `Tooltip.add` tags the resulting element, and `WailaTickHandler` fires collected callbacks **after normal provider collection**. Priority `Integer.MAX_VALUE` removes the specific value after other normal callbacks, rather than canceling Jade or replacing its registry.

ProjectE `JadeDataProvider.appendTooltip` adds `EMCHelper.getEmcTextComponent(value,1)` under `PEJadeConstants.EMC_PROVIDER = projecte:emc_provider`, and only when native server setting `lookingAtDisplay` enables it. The bridge honors that native choice by filtering **only an already-present provider-tagged element**. If the Stone milestone is missing, the client lease is stale, the viewed player does not match the current local player, or native knowledge for the **actual block item** is missing, remove that one tag; do not alter the native ProjectE value map, numeric accounting, other Jade providers, or the Divining Rod.
