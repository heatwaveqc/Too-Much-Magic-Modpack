# Regular-stage personal home placement — Progression-owned ability

**Owner design choice:** 2026-11-20. **Status:** approved design target; no new runtime implementation, quest reward change, server build, or gameplay validation is asserted by this document.

## Decision

Treat **one free Starter Home placement** as a built-in, permanent-stage **Progression benefit of `Regular`** (owner nickname **Normie**), like an innate path power but **without inventing/enrolling a new path**. It is not an FTB item/choice reward, a transferable house voucher, or a new Prefab item. The existing `NewbieMode` authority at `tmm_progression:player_mode` persists `newbie` or `regular` in `PLAYER_MODES`. The one-time housing ledger and any adapter/live code belong exclusively to **`compat/progression`** in a `feature/progression-*` branch targeting `dev/progression`.

The existing introductory **I'm Ready for Regular Mode** quest (ID `544D309000100001`, task `544D409000100001`) remains the sole player-facing graduation trigger: its own personal, non-team command reward `tmmnewbie admin graduate {p}` sets Regular, and 5 XP stays unchanged. **Do not append a housing item reward or create another graduation quest.** This avoids FTB choice-reward synchronization, item dropping/trading, inventory-full behavior and conflicting house-reward systems. `NewbieMode.graduate` is idempotent; the housing ability must likewise be idempotent and survive retries/relogs.

## Behavior contract

1. **Who has it:** any player whose current canonical mode is `regular` may claim a personal free house exactly once, even after entering a Monk/Hunter/etc. path or acquiring an eligible species. Path/class changes do not regrant it. Newbies may not build for free. This is a stage perk, not a class tree, currency, spendable skill point or perk to respec.
2. **Who owns the record:** Progression persistent, server-authoritative, UUID-scoped state. Suggested single stable capability key `tmm_progression:regular_starter_home` with `available / reserved / redeemed` settlement; no dependence on the native `builtStarterHouse` flag, inventory item count, FTB reward-claim state or scoreboard tags for ownership. Never clear `redeemed` through `regular -> newbie -> regular`, admin use, clone/respawn, death, logout, restart, team changes, path change or skill refund. Existing established characters migrated to Regular are eligible if not recorded as redeemed; explicit future migrations must protect any earlier verified grants.
3. **What it builds:** exactly one of **19 theme-level choices**: 18 original custom houses from `research/prefab-donors/houses-qa-v1.json` and **Generic** as a single choice. Generic retains Prefab 1.0.9's 15 built-in Starter House styles as substyles, **not** fifteen additional house entitlements. The authoritative allowlist must be immutable for an in-flight build and sourced from verified, integrated housing assets; no arbitrary uploaded, cloud, marketplace or player-entered structure IDs are eligible for the free entitlement. Reconcile the Adventurer's Inn board from housing PR #381 before final builds. All 18 houses are currently static generator/staging candidates in housing PR #416, not a gameplay-tested runtime release.
4. **Interaction/UI:** prefer reuse of existing Progression ability UI/commands and the provider's built-in building preview/selection UI, with a minimal adapter, over inventing a second full GUI or modifying Prefab's JAR. The **ability**, not possession of `prefab:item_house`, is the source of free-placement rights. Ordinary crafted/paid Prefab Starter House and addon blueprints keep their established behavior. Native `GuiHouse` cannot be populated with external structures by config; its source iterates the hard-coded `HouseConfiguration.HouseStyle` enum. Custom Addon has a distinct building browser for `prefab-extension` structures. A focused handoff between these providers is acceptable; do not assume both appear in a single vanilla Prefab style list.
5. **Correct free cost:** Progression authorizes exactly one placement of a selected allowlisted structure **without material payment**, and only for the owner. No global `/prefabaddon freemode`, no broad free-build mode, no unconditional reusable `prefab_custom_addon:custom_blueprint`, and no temporary free window permitting multiple submissions. The game's normal material economy for unrelated structures remains unchanged. Disable Prefab's automatic first-join Starter House grant (`newPlayersGetStartingItem=false`, `startingItem=Nothing`) in the integrator-owned config; the free Generic must not grant default loot, mineshaft resources or the 20-coal-per-furnace windfall. These were approved in the Generic review.
6. **Atomic one-time settlement:** for a placement, Progression checks canonical Regular mode, unused ledger, exact server-side template ID/metadata, correct dimension, existing claims, terrain safety and no conflicting transaction. **Reserve before any world modification**, one active construction per player; preview/cancel/preflight failure does not spend the ability. A successful finished placement **redeems** it permanently. An interrupted asynchronous placement must not be silently reset to available if it left world blocks behind; recover/reconcile the in-flight transaction or roll back partial blocks safely. Prevent concurrent requests, replayed network packets, cross-player placement, item cloning, server crash recovery duplication and save/relog races. Do not interpret an addon's “task started” return as successful completion.
7. **Provider safety and isolation:** Custom Addon 2.7.1 currently starts asynchronous builds from `BuildCustomStructurePayload`; source `AsyncBuildManager` retains its native `CustomBlueprintItem` after completion. Client-only material checks are not a reliable security boundary. Progression must enforce the server authorization for this scoped free ability; audit external unrestricted addon construction packets and cloud recall/summon separately rather than claiming all server/build economy is protected. Exact-version optional integration should fail closed and report unavailability when Prefab/Addon, required asset, or callback is missing; never unlock a generic no-cost fallback. Native Generic can follow a separate minimal provider path but must settle against the **same ledger**.
8. **No hidden second grant:** do not issue one native Prefab house plus one custom add-on house; the 19 options debit the same personal right. A preview or rejected site stays retryable. If a house is already placed and later destroyed, the ability remains used. Paid acquisition and later ordinary construction remain separate.

## Implementation ownership / dependency handoff

- **Progression engine owns:** canonical mode and entitlement checks, persistent record, simple stage-power discoverability, optional mod adapters and transaction lifecycle, lightweight targeted server validation, tests. Keep Java code in `compat/progression`, not `compat/monk` or `compat/hunter`, no independent `KubeJS` gameplay script.
- **Housing author owns:** immutable original-house source catalog/generators and approved published NBT assets from PR #416 (plus Inn board reconciliation PR #381).
- **Integration author owns:** selecting source SHA, actual mod pin/release + LDLib2 closure from PR #403, publish/stage assets, packwiz and config (auto-start house off, Generic bonus resources off), shared quest/index changes *only if required*. The existing FTB graduation quest requires **no modification** for this design.
- **Optional soft dependency:** both Prefab and Custom Addon are providers, not a hard dependency for the basic Progression mod. No fork/patch of third-party JAR is preferred. If the exact Custom Addon release offers no reliable completion/authorization seam, implement the smallest scoped compatibility hook or investigate a safer provider API; **do not silently claim the feature is config-only**.

## Acceptance / tests (not yet run)

- Newbie has no free placement; first Regular graduation enables one, shared quest teammates remain independent; an established migrated Regular has one if never previously redeemed. Admin repeats/downgrade, respawn, death, logout/restart, path/species changes and inventory loss never regenerate used eligibility.
- One Generic *or* one custom choice only, all 18 custom files and Generic style subchoices discoverable; second placement refused from a second simultaneous window, forged request, relog, creative-state glitch or different held blueprint.
- Both native and addon preview/rejection/cancel are free and safe; concurrent attempts fail closed; partial async completion and restart settle/rollback without material or block duplication; success makes one immutable redemption.
- Server alone validates choices/claims/terrain/material exemption; unrelated paid blueprints, Creative permissions, market/cloud/recall and FreeBuild remain unchanged and cannot be repurposed for free house duplication.
- Source/Java unit tests and quick Repository/Module CI + read-only Integration Preflight before merge. **No full server boot, Integration Assembly, Prism package or gameplay PASS** without separate owner authorization.
