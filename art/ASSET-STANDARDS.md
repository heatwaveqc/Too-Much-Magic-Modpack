# Asset standards v0.1
## Target and compatibility
Minecraft Java 1.21.1 (resource-pack format 34), NeoForge. Native 64 texels per standard 16-texel block/item tile, equivalent to 4x source-grid units; never mechanically enlarge an old texture as the finished deliverable. Rectangular sheets retain proportional aspect, layout and native UVs. Identify actual texture dimensions and rendering contract from the pinned archives: some mods already use high resolution and some sheets cannot be blindly scaled. For non-tile sprites, UI, custom models, particle sheets and entity skins, document intended dimensions and factor with specific renderer/atlas evidence. A 32x32 native 2-tile strip is not a single 64x64 sprite. Respect native artistic masks and alpha semantics. No new geometry unless separately requested and compatibility reviewed.

## File rules
- Production paths match the exact upstream resource location and case: too-much-magic-hd/assets/<namespace>/textures/<relative-path>.png; lowercase namespace/file names supported by resource-location rules. Do not infer namespace from mod title. Preserve texture references in JSON, object-model UVs, layout, emissive layers, dye masks and animations. Preserve adjacent .png.mcmeta metadata if necessary (validate shape/frame counts before changing). Inspect overlays, nested JARs and generated resources separately; don't presume all paths can be found in a simple top-level scan.
- PNG lossless RGBA/RGB; sRGB working space; correct transparent background when expected. No JPEG, watermarks, metadata containing secrets, baked checkerboard/mockup background, borders from a contact sheet, arbitrary resizing of UV islands, or alpha fringes.
- Block faces: exactly 64x64 per standard tile, repeat-compatible edges, no perspective, opaque if native opaque. Review 3x3 tiled preview; consistent top/side/end grain, connected texture masks/indices. Tile border continuity is an art review, not guaranteed by automated check.
- Items: typically 64x64; preserve original orientation and distinct silhouette; transparent safe padding proportional to upstream; test 16px and 32px slot views on light/dark backgrounds. Layered/dyed items retain matching alignment; do not bake enchantment glint, shadows outside asset or renderer-supplied overlays.
- Animated strips: same frame layout and ordering unless exact atlas metadata explicitly changes; preserve cadence and interpolation settings. Animated 64x64 tiles produce 64x(64*N) vertical sheet if original uses vertical frame order. Respect non-square declared frame sizes. Inspect sequence as motion and seam between last/first frames.
- Entity/armor/model atlases: preserve native UV proportions and layer semantics; extend scaled source template proportionally, only paint relevant islands. Match seam boundaries, mirrors, species patterns; inspect front/back/sides and animated poses in game. Some renderers use hardcoded coordinates; require a compatibility probe.
- GUI: preserve inventory slots, nine-slice margins, font/icon spacing, tooltip contrast and pixel coordinates using correct atlas/sprite scaling; never replace text with baked images; verify GUI scale and mod-specific render. Fonts, status effect icons, particles, custom sky atlases, connected textures and shader/PBR assets need class-specific rules. PBR is optional later, not baseline scope.
- A texture in original archive may be unused, generated, duplicate, incompatible or not intended to override. Keep inventoried; exceptions use owner-approved unchanged/excluded status and reason. Exact shared assets need namespace collisions assessed. No substitution without review.
 
## Acceptance
Each row records original archive and SHA-256, upstream asset path/hash/dimensions, target path/dimensions, category, status, batch, style version, provenance, output SHA-256, structural and visual QA, reviewer and date, game test state, exception reason if applicable. Review each texture in a family, not just contact sheet representative. Validate no unintended namespace/path, corrupt PNG, bad dimensions, orphan metadata or accidental upstream copy. Manual art review is required before 'approved'; client launch and game view before 'game-tested'. Transparent edge, color readability, tiling, animation and renderer regressions are distinct review points.
