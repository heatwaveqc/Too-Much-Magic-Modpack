# Coverage registry
Current category layer: [CLASSIFICATION-STATUS.md](CLASSIFICATION-STATUS.md), `classification-index.json` and its hash-checked shards. `load_registry` joins all 42,542 category/family/deliverable/flag/evidence records to source facts by key and applies the 707 exact-provenance `excluded-approved` decisions. A primary category may be null when the native use is unresolved. Dynamic constructor patterns have a separate provisional state. Family grouping and category proposals never constitute owner approval. Seventeen saved review candidates have blocked approval records; there are no active production PNGs until approval. Prior pilot records are retained in Git history and the original branch.

Current evidence: [INVENTORY-STATUS.md](INVENTORY-STATUS.md). The frozen archive path scan is populated. `inventory.json` schema 2 references hash-checked gzip JSON catalog shards containing source facts only and keeps draft/review decision rows separately. Use `catalog_registry.load_registry` to expand them and merge decisions by exact key; do not treat the 16 decision rows as the whole inventory. A plain schema 1 inventory remains supported by the validator.

The initial roster seed is a frozen decision snapshot from the integration branch, **not** verified archive/texture coverage. Scope includes vanilla client plus all installed content-bearing mods, approved future mods and addons. The authoritative required texture denominator can only be established after inventory of exact archives and special runtime assets. No eligible namespace or asset is omitted by assuming a mod is just a library.

- roster.json: seed of owner decisions/installed flags at pinned integration revision; inspect actual Packwiz metadata and archive hash before use; reconcile future revisions.
- inventory.json: populated schema 2 catalog index and per-key decisions. Reproduce with tools/collect_inventory.py into scratch, then reconcile with tools/catalog_registry.py, preserving unchanged decisions. Asset keys = full assets/<namespace>/textures/... path, source archives may collide; list all upstream sources and choose active precedence explicitly.
- Each asset has status pending / drafted / reviewed / approved / validated / game-tested / unchanged-approved / excluded-approved / blocked. Pending/blocked are not complete; exceptions not counted as retextured. Registry entries track source(s), target dims, review evidence, output hash, provenance and exception justification. No guessed rows. Do not erase review decisions via regeneration. Report retextured and game-tested counts separately; inventory completeness is separate.
- Archive closure, nested archives, non-PNG, generated resources, overlays, atlas metadata and model references require follow-up. Track source coverage and review gaps alongside exact output counts.

## Art exclusions and inherited assets
Read [scope-exclusions.json](scope-exclusions.json) for the initial owner-directed art-only blacklist. Reconcile exact source archive IDs to inventory rows and record excluded-approved reasons; preserve shared assets and report exclusions separately from eligible production scope and total inventory. Never change the runtime manifest or claim excluded native textures were retextured. Track master template/host texture ID and SHA-256 for derived ore, infused, recolored and rune-family assets, and record mixed mosaic or aligned side-by-side evidence as required by [category standards](../CATEGORY-STANDARDS.md).
