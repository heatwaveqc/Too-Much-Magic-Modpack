# Local art tooling
For v0.2 use `renderer_evidence.py` on provider-verified archives plus official Mojang class mappings, then `classify_textures.py --inventory art/registry/inventory.json --renderer-evidence /scratch/renderer-evidence.json --out art/registry --csv /scratch/Texture-categories.csv`. This resolves inherited model faces, native atlas/font/particle use and exact renderer texture literals. Dynamic path recipes remain provisional; unresolved uses stay null. Category shards and evidence are hash/source-signature checked by `load_registry` and static validation. Only native facts and technical references are committed, not class files/mappings/archives.

`pilot02_samples.py --inputs /scratch/original-generated-inputs.json --out /scratch/review` creates review-only PNGs, material derivatives, 5x5 proofs and offline model faces; it refuses an output location inside the repository. Input JSON maps the selected generated diamond/iron/chestplate/material names to original source files. The old selected project art is read at its exact Pilot 01 commit. A failed/unused candidate never enters the pack. See the saved master identities and prompts in reviews/pilot-02. The v0.1 generation/review entry points below are retained as historical tooling, not a workflow for staging unapproved v0.2 assets.

Schema 2 workflow: `acquire_sources.py` obtains only frozen art-inspection archives and verifies provider digests; `collect_inventory.py` rechecks them, scans nested resources, overlays and renderer JSON, and projects pinned first-party source assets without building a JAR. `catalog_registry.py` stores compact deterministic gzip JSON facts and preserves decision rows. These are registry data, not archived upstream artwork. `validate.py` checks every shard hash/count before validating output assets. See registry/INVENTORY-STATUS.md for the exact baseline and limits.

`prepare_pilot.py` and `review_pilot.py` require Pillow and NumPy for local original-art processing; generation inputs remain in scratch. Their outputs are the selected PNGs and small original-art review board, not a distributable ZIP. Inventory and static CI otherwise use the Python standard library.

Python 3.10+ standard library only. Read ../PRODUCTION-PIPELINE.md first.
Example from repo root: python art/tools/inventory.py --source vanilla=/local/1.21.1.jar --source botania=/local/botania.jar --out /tmp/art-inventory.json
