# Art workstream contract
Read the repository root AGENTS.md, README.md, STYLE-GUIDE.md, ASSET-STANDARDS.md, PRODUCTION-PIPELINE.md and registry/README.md before writing. This document specializes, not overrides, repository governance.
 
- **Ownership:** dev/art is the durable art integration branch. One designated art integration writer. Agents branch from current dev/art using feature/art-<family>-<batch>, edit only art/ paths assigned in the batch manifest, open reviewed PRs to dev/art, and retain exact source SHA. Check existing work and claims first. No edits to gameplay code, packwiz, config, quests, or test/full-integration. Do not copy gameplay branches into art. Refresh roster inputs by frozen integration SHA, not by replaying whole trees. Main is the policy base. Never delete dev/art or unresolved/claimed branches.
- **Scope:** native 64x block/item texels; proportional atlases. Full vanilla and all actual selected content mods, including add-ons and future changes. A library is not presumed asset-free; inspect actual archive. Preserve registry IDs, layouts, visual semantics, and runtime behavior. Default Cathobb stays until separately approved.
- **Art rights:** make original artwork. References guide materials and visual language, not pixel tracing, image-to-image reconstruction, or republishing. Do not upload third-party images or JARs unless exact written rights support that use; record attribution and license. Official linked gallery pages/remote previews are reference-only. Never include upstream assets as placeholders. Treat locally inspected upstream data as ephemeral. Respect Minecraft and mod authors' terms. Do not imply affiliation.
- **Evidence:** inspect actual input archive SHA-256 and asset paths; no fabricated inventory entries, filenames or source identity. Distinguish expected, inventoried, drafted, reviewed, approved, validated, and in-game-tested. Asset review is not a game test. Explicit unchanged exceptions require owner approval and count separately. Review sprite at 1:1 and 16/32px; inspect seams, UV and animation where relevant. Keep no generated/rejected candidates in Git.
- **Execution:** stop before production-scale creation until owner approves representative pilot. Once approved, autonomously finish small related batches, with recorded style version, prompt/tool or method, output hashes, review evidence, exact paths and next actions. Do not ask for routine approvals after the visual target is approved; ask only about new artistic choices, ambiguous layout, license or destructive actions. If image generation or binary transport is unavailable, record blocker, finish inventory/guidance and do not mark textures created. Work must be restartable from registry and branch.
- **QA:** source/static-only art validation and isolated unit tests are fine. No automatic full NeoForge server boot, source assembly, Prism package or publication. Standalone art ZIP creation and release require separate explicit owner authorization; no automatic release. Test manual in-game art previews only with approved client setup. Never claim source checks passed in-game. No credentials or tokens in repo.
- **Storage:** retain only selected finalized PNGs, intentional models/metadata, original reference swatches and small representative review sheets. No bulk intermediate output, upscaled duplicates, archive builds, downloads, screenshots of copyrighted gallery art, or other binary caches. Review repository growth as final assets accrue; consider scoped Git LFS or a separate art repo only after owner approval.
